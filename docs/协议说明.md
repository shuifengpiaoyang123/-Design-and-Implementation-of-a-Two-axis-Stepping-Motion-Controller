# 串口通信协议说明（v1.0）

> 适用：两轴步进运动控制器（项目一）
> 串口：USART1 / 板载 CH340 → PC 端 COMx，**115200 bps，8 数据位，无校验，1 停止位**
> 文件对应：下位机 `Core/Src/protocol.c`、上位机 `host/protocol.py`

## 1. 为什么用"一行文字"

任务书 4.4 建议采用可直接用串口助手读写的文本格式，理由有三条：

1. **可以脱离上位机测下位机**。第 3 周要求先用手工发指令确认下位机正确，二进制协议做不到。
2. **调试成本低**。一条 `MOV X-12.5 F20` 一眼能看出参数对不对，出错时不用查表换算字节。
3. **可扩展到项目三**。G 代码本身就是逐行文本（`G01 X10 Y20 F300`），同一套"按行接收 + 查首个词分派"的结构可以直接复用，只需在分派表里加几行。

代价是比二进制多几个字节，但在 115200 下一条指令不到 1 ms，远小于 300 ms 的应答预算，可以接受。

## 2. 帧格式

```
一帧 = 一行 ASCII 文本 + \n        （\r 忽略，便于串口助手直接发送）
```

- 参数之间用**一个空格**分隔，大小写不敏感（下位机内部统一转大写）。
- 行缓冲 96 字节，超长行整行丢弃（防止上位机异常时把 RAM 撑爆）。

## 3. 指令表

| 功能 | 格式 | 说明 | 应答 |
|---|---|---|---|
| 心跳 | `PING` | 上位机每 200 ms 发一次，配合 F8 通信超时 | `PONG` |
| 连续运动 | `JOG X+ F20` | 轴号 + 方向 + 速度(mm/s)，F 省略时默认 10 | `OK` |
| 定长运动 | `MOV X-12.5 F20` | 相对位移，带符号即方向 | `OK` |
| 绝对定位 | `MOVA X100 F30` | 机械坐标，**须已回零** | `OK` / `ERR,3` |
| 两轴联动 | `LINE X10 Y5 F20` | 斜线：两轴同时启动、同时到达；F 为沿轨迹的合成速度 | `OK` / `ERR,6` |
| 停止 | `STOP X` 或 `STOP` | 指定轴 / 两轴，走减速曲线 | `OK` |
| 急停 | `ESTOP` | 立即封脉冲 + 报警锁定（码 2）+ 作废回零 | `OK` |
| 回零 | `HOME X` | 走 F4 五阶段状态机 | `OK` |
| 复位 | `RESET` | 清报警；**不清除"需重新回零"** | `OK` |
| 参数设置 | `SET X LEAD=5 PPR=1600 ...` | 可只带部分参数，见第 5 节 | `OK` / `ERR,2` |
| 参数读取 | `GET X` | 返回该轴全部参数 | `OK X LEAD=...` |
| 运动记录 | `TRACE X` | 武装：该轴**下一次**运动开始按 1 ms 记录 | `OK` |
| 记录上传 | `DUMP` | 返回 `<TR ...>` + N 行数据 + `<TREND>` | 见 6.2 |
| 帮助 | `HELP` | 列出指令名 | 一行文本 |

### 3.1 联动指令 LINE 的速度分配（挑战要求②）

`LINE` 不下发插补点，而是把合成进给速度**按位移比例**分给两轴：

```
L  = √(Δx² + Δy²)          轨迹长度
kx = |Δx| / L ,  ky = |Δy| / L
vx = F·kx ,  vy = F·ky      （任一轴超自身 Vmax 时整体降 F，比例不变）
ax = A·kx ,  ay = A·ky      （A 取各轴 ACC/k 的最小值，保证不超设定加速度）
```

因为两轴的**速度曲线形状完全相同**（同一时间轴、等比缩放），任意时刻都有
`vx/vy ≡ |Δx|/|Δy|`，所以轨迹是严格直线；又因为加速时间 `F/A` 相同、匀速时间相同，
两轴**必然同时到达**。

实测（δ=0.003125 mm，F=20 mm/s）：

| 指令 | 实测 | 结果 |
|---|---|---|
| `LINE X10 Y10 F20` | 两轴同帧到位，全程 Y−X 偏差 0.000 mm | 严格 45° |
| `LINE X-20 Y-5 F20` | vX=−19.40，vY=−4.85，比值 0.250 | 严格 4:1 |

> 这就是项目二 DDA 插补的最简形式：不改动四层架构，只在运动规划层入口按比例缩放每轴的
> `v_cmd` 与 `acc` 即可。项目二换成真正的基准脉冲插补时，替换的正是这一层的入口函数。

### 3.2 圆弧插补指令 G02 / G03（项目二，固件与上位机均已实现）

    G03 X<ΔX> Y<ΔY> I<i> J<j> F<feed>     逆时针（CCW）
    G02 X<ΔX> Y<ΔY> I<i> J<j> F<feed>     顺时针（CW）

- `I/J`：**圆心相对起点**的偏移（标准 G 代码语义，模态无所谓，这里一条指令一段弧）
- `ΔX/ΔY`：**终点相对起点**的位移；两者同时为 0 且 I/J 有值 = **整圆**
- `F`：切向进给速度 mm/s（沿弧长，不是单轴速度）
- 上位机的"半径 + 角度"输入只是便利：R、起始角、扫角 → 由 `host/arc.py` 反算出 I/J/ΔX/ΔY 再发送，
  下位机只认 I/J 一种形式

例：从当前位置出发，绕左下方 R=10 mm 的圆心走一整圈（逆时针）：

    G03 X0 Y0 I-10 J0 F10

从起点沿顺时针扫 210°（R=15，起点在圆心正上方）：

    G02 X-7.5 Y-27.99 I0 J-15 F10

**固件实现要点**（详见 `docs/圆弧插补仿真验证.md`，仿真已验证）：

1. 切向速度必须用 `v = ω·R`，不能直接用指令 F（否则起步瞬间跳速）
2. 速度方向取本毫秒**中点角** θ + dθ/2 —— 用末端角会让轨迹持续外扩（R=10 一圈 +10 µm）
3. 加减速折成角加速度 `α = A/R`，ω 走梯形 + √(2α·剩余角) 制动，与直线同构
4. 允许"该轴速度为 0 时换向"——整圆在 90°/270° 处正好是正弦过零点，物理安全
5. 终点判定用 `已扫角 == 应扫角`，不要用 position == target，也不要 atan2 跨 ±π 判断

**实现位置**：固件 `stepper.c: Stepper_MoveArc / Stepper_ArcTick`（约 170 行）、
`protocol.c: ArcCommon / CmdG02 / CmdG03`；上位机 `host/arc.py`（几何）、
`host/arc_view.py`（预览+半径误差画布）、界面"圆弧插补 G02/G03"页。

**实测（R=8 整圆 F=8，10 Hz 采样）**：半径误差 max 3.1 µm（1 个当量）、mean 1.0 µm、
终点误差 0.0 µm、用时 6.34 s（理论 6.32 s）。完整数据见 `docs/圆弧插补仿真验证.md` 第 6 节。

## 4. 应答与错误码
```
OK
ERR,<code>
```

| 码 | 含义 | 触发场景 |
|---|---|---|
| 1 | 语法错误 | 缺轴号、方向不是 +/−、缺参数 |
| 2 | 参数越界 | 速度超 Vmax、PPR 不在 8 档、加速度超 10~500 等 |
| 3 | 未回零 | 未回零就发 `MOVA` |
| 4 | 超出软限位 | 目标位置出 0~240 |
| 5 | 报警锁定中 | 限位/急停后未 `RESET` |
| 6 | 该轴忙 | 轴在运动中又发运动/回零指令 |
| 7 | 未知指令 | 首词不在分派表 |

**每条指令都必须有应答**，上位机据此判断成败，并在 300 ms 内收不到时提示超时（运动类指令**不自动重发**，避免重复运动）。

## 5. 参数（F9）

| 键 | 含义 | 范围 | 默认 |
|---|---|---|---|
| `LEAD` | 丝杠导程 mm | 1 ~ 20 | 5 |
| `PPR` | 每转脉冲数 | 400/800/1000/1600/2000/3200/4000/6400 | 1600 |
| `DIRINV` | 方向取反 | 0 / 1 | 0 |
| `ACC` | 加速度 mm/s² | 10 ~ 500 | 200 |
| `VMAX` | 最高速度 mm/s | 1 ~ 60，且 ≤ 25 kHz × δ | 50 |
| `SLMIN` / `SLMAX` | 软限位 mm | 0 ~ 250，下限 < 上限 | 0 / 240 |
| `HF` / `HS` | 回零快 / 慢速 mm/s | 5~20 / 0.5~2 | 10 / 1 |

**Vmax 为什么有上限**：50 kHz 节拍下脉宽要占 2 个节拍，输出频率上限 25 kHz，
所以 `v_max = 25000 × δ`。1600 细分时约 78 mm/s，6400 细分时只有 19.5 mm/s —— 上位机切档位时要同步刷新这个上限并挡住超限输入。

改 `LEAD` 或 `PPR` 后下位机自动作废"已回零"标志，因为脉冲当量变了，旧坐标不再有意义。

示例：

```
SET X LEAD=5 PPR=1600 DIRINV=0 ACC=200 VMAX=50 SLMIN=0 SLMAX=240 HF=10 HS=1
OK
GET X
OK X LEAD=5.000 PPR=1600 DIRINV=0 ACC=200.0 VMAX=50.00 SLMIN=0.000 SLMAX=240.000 HF=10.00 HS=1.00 DELTA=0.003125
```

## 6. 状态上报与运动记录

### 6.1 状态上报（F10，每 100 ms）

```
<ST X=12.500,25.00,RUN,H1 Y=0.000,0.00,IDLE,H0 LIM=0100 ALM=0>
```

| 字段 | 含义 |
|---|---|
| `X=位置,速度,状态,H回零` | 位置 mm（3 位小数）、速度 mm/s（带符号）、状态、H1=已回零 |
| 状态 | `IDLE` 空闲 / `RUN` 运动中 / `ALM` 报警 |
| `LIM=abcd` | 依次为 X−、X+、Y−、Y+，1 = 触发（高电平） |
| `ALM` | 0 无 / 1 硬限位 / 2 急停 / 3 回零失败 |

选择 100 ms 的原因：人眼对位置显示的刷新需求是 10 Hz，而任务书要求遮挡限位后 200 ms 内界面更新，100 ms 上报留了一倍余量。

### 6.2 运动记录上传（F12）

```
TRACE X          → OK          （武装，下一次运动开始记录）
MOV X50 F50      → OK          （运动，1 ms 采样脉冲增量，最多 3000 点）
DUMP             → <TR X N=1244 DT=1 STOP=-1>
                   12
                   25
                   ...
                   <TREND>
```

- `N`：采样点数；`DT`：采样间隔 ms；`STOP`：收到停止指令时的采样序号，无则 −1。
- 数据行是**每毫秒的脉冲增量**（无符号，0~50），上位机用 `v = ΔN·δ/0.001`、`x = ΣΔN·δ` 还原曲线。
- 传增量而不是传位置，是为了 3000 点只占 6 KB RAM（位置是 32 位，增量 16 位就够）。

## 7. 安全相关的分工

任务书 2.5 强调：**串口有延时，安全保护必须在下位机**。因此：

| 保护 | 下位机实现 | 上位机职责 |
|---|---|---|
| 硬限位 F5 | EXTI 中断里立即封脉冲 + 报警锁定 | 显示报警原因、提供复位按钮 |
| 软限位 F6 | 指令入口校验 + 点动目标钳位 | 发送前预判并提示，不发送 |
| 急停 F7 | 按钮 EXTI 与 `ESTOP` 指令同一路径 | 醒目按钮 + F12/Esc 快捷键 |
| 通信超时 F8 | 500 ms 无报文自动减速停 | 200 ms 心跳；断开前先发 `STOP` |

上位机**不做**任何位置推算：所有位置、速度、状态一律取自 `<ST>`，避免"界面显示和实际不一致"。
