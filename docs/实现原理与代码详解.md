## 1. 第一层：脉冲是怎么发出来的（相位累加器）

### 1.1 先想清楚"不能怎么做"

步进电机的转速由**脉冲频率**决定。最直觉的做法是：算出现在该多快，然后改定时器的 `ARR`（自动重装值），让定时器每溢出一次就发一个脉冲。

这个做法在单轴、单速度下能用，但有三个致命问题：

1. **改 ARR 有延迟**：写寄存器后，当前计数周期还要走完才生效，速度变化不连续；
2. **频繁改 ARR 会抖动**：每个周期都要进中断重算，中断响应抖动直接变成脉冲抖动 → 电机啸叫、丢步；
3. **两轴没法共用一个定时器**：两轴速度不同，需要不同频率，改 ARR 只能服务一个轴。

### 1.2 用"相位累加器"把频率问题变成"累加问题"

做法是：定时器频率**固定 50 kHz 不变**（TIM2：72 MHz / 72 / 20 = 50 kHz，每 20 µs 进一次中断），
频率通过"每拍给一个 32 位累加器加多少"来控制。

```c
/* stepper.c:1199  Stepper_Axis_Tick() —— 每 20 µs 执行一次 */
old_phase = m->phase;
m->phase += m->increment;          // 32 位无符号累加，溢出自动回绕

if (m->phase < old_phase)          // 回绕 = 溢出一次 = 走一个脉冲当量
{
    HAL_GPIO_WritePin(m->step_port, m->step_pin, GPIO_PIN_RESET);  // 拉低
    m->pulse_active = 1;
    m->position += m->direction;   // 位置计数 ±1
}
```

**原理推导（DDS 直接数字合成）：**

累加器是 32 位，量程 `2^32 ≈ 4.29e9`。每拍加 `K`，那么溢出一共需要 `2^32 / K` 拍。
每溢出一次发一个脉冲，所以：

```
脉冲频率 f = (每秒拍数) / (每脉冲拍数) = ft / (2^32 / K) = K · ft / 2^32
```

反解出"想要速度 v 时该给多少 K"：

```
v = f · δ        （δ = 脉冲当量，走一个脉冲对应多少毫米）
f = v / δ

K = f · 2^32 / ft = v · 2^32 / (δ · ft)
```

代码里把常数项提前算好，存成 `k_gain`：

```c
/* stepper.c:124  Stepper_Recompute() */
m->delta  = m->lead / (float)m->ppr;                            // δ = 5 / 1600 = 0.003125 mm
m->k_gain = 4294967296.0f / (m->delta * (float)STEPPER_TICK_HZ); // = 2.7488e7
```

于是运行时只需要一次乘法：

```c
/* stepper.c:159  Stepper_SpeedToIncrement() */
k = v * m->k_gain;
if (k > (float)INCREMENT_MAX) k = (float)INCREMENT_MAX;   // 0x7FFFFFFF，防止一拍出多个脉冲
return (uint32_t)k;
```

**代入实际数字验证**（1600 细分、导程 5 mm）：

- δ = 5 / 1600 = **0.003125 mm**（3.125 µm）
- 走 10 mm → `N = L/δ = 3200` 个脉冲
- 速度 50 mm/s → `f = 50/0.003125 = 16000 Hz`
- K = 16000 × 2^32 / 50000 = 1.3744e9（小于 2^31，安全）

### 1.3 为什么这个方案比改 ARR 好

| 维度 | 改 ARR | 相位累加器 |
|---|---|---|
| 速度切换 | 要等当前周期走完，有 1 个周期的滞后 | 下一拍立即生效 |
| 低速平滑性 | 低频时抖动明显 | 脉冲间隔误差 ≤ 1 拍（20 µs），可接受 |
| 多轴 | 一轴一个定时器 | **一个定时器算所有轴**（`Stepper_TIM_Callback` 里依次调 `Stepper_Axis_Tick`） |
| 中断负担 | 每来一个脉冲进一次中断 | 固定 50 kHz，与速度无关（高速时反而更省） |
| 代码 | 要处理重装值边界 | 一次加法 + 一次比较 |

任务书 2.3 节要求"50 kHz 节拍下实现脉冲发生"，本质就是要你用这个结构。

### 1.4 三个容易踩的硬件细节

**① 脉宽必须有两个节拍**

驱动器要求脉冲低电平宽度 ≥ 2.5 µs（本项目给 20 µs）。但中断里只能拉低，不能 `HAL_Delay`，所以用"本拍拉低、下一拍释放"的方式：

```c
if (m->pulse_active)                       // 上一拍拉低过
{
    HAL_GPIO_WritePin(m->step_port, m->step_pin, GPIO_PIN_SET);  // 本拍释放
    m->pulse_active = 0;
}
```

代价是**一个脉冲至少占 2 拍**，所以输出频率上限是 `ft/2 = 25 kHz`，不是 50 kHz。
速度上限随之变成 `v_max = 25000 × δ`：

| 细分 PPR | δ (mm) | 速度上限 (mm/s) |
|---|---|---|
| 800 | 0.00625 | 156.2 |
| 1600 | 0.003125 | 78.1 |
| 3200 | 0.0015625 | 39.1 |
| 6400 | 0.00078125 | **19.5** |

代码里对应：

```c
/* stepper.c:881 */
static float Stepper_VmaxLimit(const StepperAxis *m)
{
    return 25000.0f * m->delta;
}
```

这就是任务书里"6400 细分时速度被限制"的来历，也是 `SET PPR` 之后必须重算 `Vmax` 的原因。

**② 方向信号要在出脉冲前稳定 ≥ 1 ms**

驱动器采样方向信号有建立时间要求。代码用"空跑 50 拍"实现：

```c
m->start_wait = 50;        // 50 × 20 µs = 1 ms
...
if (m->start_wait > 0) { m->start_wait--; return; }   // 期间不出脉冲
```

`start_wait` 还有一个副作用（后面联动会用到）：**两轴都设 50 拍，所以两轴的第一个脉冲一定落在同一拍上**。

**③ 方向只能在速度为 0 时切换**

`Stepper_Begin()` 里先写方向、再把速度清零，保证切换瞬间没有脉冲在跑。运行中改方向会丢步甚至反转抖动。

### 1.5 中断里读写共享变量的安全性

`phase`、`increment`、`position`、`target` 都声明为 `volatile`，因为它们被两个上下文同时访问：
- `increment` 由 1 ms 中断写、50 kHz 中断读
- `position` 由 50 kHz 中断写、主循环读

设计上遵守**单写者原则**：
- `increment` 只由规划层（1 ms）写，脉冲层只读 → 32 位对齐写入是原子的，不会读到"半个数"
- `position` 只由脉冲层写 → 主循环读到的要么是旧值要么是新值

需要跨层修改时用关中断保护，例如 `Stepper_Stop`：

```c
__disable_irq();
...
m->target = m->position + m->direction * n;
m->state  = STEPPER_DEC;
__enable_irq();
```

否则可能出现"读完 position、还没来得及改 target，中断里已经多走了一个脉冲"的竞争。

## 2. 第二层：速度怎么规划（1 ms 梯形/三角形）

### 2.1 一条公式解决所有问题

每毫秒（`SysTick_Handler` → `Stepper_Planner_1ms`）对每个轴做：

```
v ← min( v + a·T ,  v_cmd ,  √(2·a·s) )
```

其中 `T = 1 ms`，`s = 剩余距离(mm) = |target − position| × δ`。

三条限制分别对应三种含义：

| 项 | 含义 | 什么时候生效 |
|---|---|---|
| `v + a·T` | 加速度限制，每毫秒最多加速 a·T | 起步段 |
| `v_cmd` | 用户设定的目标速度 | 匀速段 |
| `√(2·a·s)` | **制动距离限制**，速度不能超过"还能刹住"的值 | 减速段 / 短行程 |

`√(2·a·s)` 的来源是匀减速公式 `v² = 2·a·s`：剩下 s 毫米、减速度 a，那么当前速度最高只能是 `√(2as)`，否则刹不住会冲过目标。

代码：

```c
/* stepper.c:1154 */
remain = m->target - m->position;  if (remain < 0) remain = -remain;
v_brake = sqrtf(2.0f * m->acc * (float)remain * m->delta);

switch (m->state)
{
case STEPPER_ACC:
    m->v_plan += m->acc * STEPPER_TP_S;
    if (m->v_plan >= m->v_cmd) { m->v_plan = m->v_cmd; m->state = STEPPER_CRUISE; }
    if (m->v_plan >  v_brake)  { m->v_plan = v_brake;  m->state = STEPPER_DEC; }
    break;

case STEPPER_CRUISE:
    m->v_plan = m->v_cmd;
    if (m->v_plan > v_brake)   { m->v_plan = v_brake;  m->state = STEPPER_DEC; }
    break;

case STEPPER_DEC:
default:
    m->v_plan = v_brake;        // 每毫秒用剩余距离反算
    break;
}

m->increment = Stepper_SpeedToIncrement(m, m->v_plan);
```

### 2.2 为什么这样写就不会冲过目标（误差自校正）

关键在减速段：**不是"按固定斜率往下减"，而是每毫秒用当前剩余距离重新算一次允许速度**。

假设某一毫秒因为中断延迟多走了 3 个脉冲（少算了距离），下一毫秒 `remain` 变小，`√(2as)` 也随之变小，速度自动压低，把多走的补回来。
这叫**闭环式规划**——虽然没有编码器反馈，但"用脉冲计数当反馈"已经足够消除累积误差。

上位机侧的实测证据：`MOV X10 F20` → 实际 10.000 mm；往返回到原点误差 0.000 mm。

### 2.3 短行程为什么自动变成三角形

行程很短时（比如 1 mm @ 50 mm/s），加速还没加到 `v_cmd`，`√(2as)` 就已经小于当前速度了——`ACC` 分支里的第二个 `if` 立即把状态切到 `DEC`。

所以**不需要单独判断 `L < v²/a`**，也不需要写"三角形模式"的代码，同一个公式自然退化。这一点是这套写法最漂亮的地方。

实测：`MOV X1 F20` 精确到位 1.000 mm，理论峰值速度 `√(a·L) = √(200×1) = 14.1 mm/s`（远低于 20 mm/s）。

### 2.4 精确到位靠的是脉冲计数，不是速度

速度规划只决定"这一毫秒出多少个脉冲"，**真正判断到位的是脉冲层的整数比较**：

```c
/* stepper.c:1234 */
if (m->state != STEPPER_IDLE && m->position == m->target)
{
    m->increment = 0;
    m->v_plan    = 0.0f;
    m->state     = STEPPER_IDLE;
}
```

因为 `position` 只在出脉冲时 ±1，`target` 是整数脉冲数，所以"停在目标上"是**逐个脉冲判定**的，理论误差 0 个脉冲（3.125 µm）。
这比"速度降到 0 就认为到了"要可靠得多——后者在 1 ms 量化下必然多走 1~2 个脉冲。

### 2.5 停止有两种，别混用

| 函数 | 行为 | 适用场景 |
|---|---|---|
| `Stepper_Stop(id)` | **减速停**：把 target 改到"当前位置 + 制动距离"，让曲线自己收尾 | 用户点停止、掉线保护、回零第一阶段 |
| `Stepper_Halt(id)` | **立即封**：`increment = 0`、状态置 IDLE，硬停 | 硬限位、急停、回零低速触发点 |

```c
/* stepper.c:515 Stepper_Stop() 核心 */
d = m->v_plan * m->v_plan / (2.0f * m->acc);   // 制动距离
n = (int32_t)(d / m->delta) + 1;               // 换成脉冲数
m->target = m->position + m->direction * n;    // 目标改成"刹停点"
m->state  = STEPPER_DEC;                       // 交给 √(2as) 收尾
```

为什么高速时不能直接 `Halt`：50 mm/s 突然断脉冲，转子有惯性，会越过目标甚至丢步（下一次运动位置就全错了）。

### 2.6 `sqrtf` 的开销够不够

STM32F103 没有硬件 FPU，`sqrtf` 是软件实现，实测约 5~8 µs/次。每毫秒 2 个轴 = 最多 16 µs，占 1 ms 的 1.6%，完全够。
如果以后加第三、第四轴，可以把 `v_brake` 改成"每 2 ms 算一次、中间线性插值"，但不建议现在就优化——可读性更重要。

## 3. 轴对象：为什么两轴共用一套代码（F11）

`StepperAxis` 把所有和"某一根轴"相关的东西打包在一起：

```c
typedef struct {
    /* 引脚 */
    GPIO_TypeDef *step_port; uint16_t step_pin;
    GPIO_TypeDef *dir_port;  uint16_t dir_pin;
    GPIO_TypeDef *lim_neg_port; uint16_t lim_neg_pin;
    GPIO_TypeDef *lim_pos_port; uint16_t lim_pos_pin;

    /* 参数 */
    float acc, acc_cmd, vmax, delta, k_gain;
    float home_fast, home_slow, sl_min, sl_max, lead;
    uint16_t ppr;  uint8_t dir_inv;

    /* 运动记录 */
    volatile uint8_t tr_on; volatile uint16_t tr_n; volatile int32_t tr_last;

    /* 脉冲发生层 */
    volatile uint32_t phase, increment;
    volatile uint8_t  pulse_active; volatile uint16_t start_wait;

    /* 运动规划层 */
    volatile int32_t position, target;
    volatile float   v_cmd, v_plan;  volatile int8_t direction; volatile uint8_t state;

    /* 回零与报警 */
    volatile uint8_t home_state; volatile uint16_t home_timer;
    volatile uint8_t homed, alarm, alarm_code;
} StepperAxis;

static StepperAxis motor[STEPPER_NUM];     // STEPPER_NUM = 2
```

所有函数都接受 `uint8_t id`，内部 `StepperAxis *m = &motor[id]`，**没有一处为 Y 轴写第二份逻辑**。

这就是任务书 F11「两轴实例化」的评分点：验收时老师可能会问"加第三轴要改多少行？"——答案是：改 `STEPPER_NUM`、加一次引脚赋值、在 `Stepper_TIM_Callback` 里多调一次 `Stepper_Axis_Tick`，运动逻辑一行不用改。

## 4. F4 回零：五个阶段为什么要这么切

### 4.1 状态机

```
① FAST      负向 home_fast(10 mm/s) 趋近
              │ 负限位触发
              ▼
② WAIT1     减速停（Stepper_Stop），等 state==IDLE
              │
              ▼
③ BACKOFF   正向 home_slow(1 mm/s) 退出，等开关释放
              │ 开关释放
              ▼
④ WAIT2     立即 Halt，等停稳
              │
              ▼
⑤ SLOW      负向 1 mm/s 二次趋近
              │ 触发 → Halt + position = 0（这就是机械零点）
              ▼
⑥ WAIT3 → TOZERO   正向走 +2 mm（HOME_OFFSET_MM）→ homed = 1
```

代码在 `stepper.c:649 Stepper_HomeTick()`，由 1 ms 规划节拍驱动（不额外占定时器）。

### 4.2 每一步的设计理由

| 阶段 | 为什么这么做 | 如果省略会怎样 |
|---|---|---|
| ① 快速 10 mm/s | 大行程快速找开关，10 mm/s 不算快，允许后续减速 | 用 50 mm/s 找开关，可能撞上去停不住 |
| ② 减速停 | 10 mm/s 下减速距离约 0.25 mm，安全 | 直接硬停有冲击，机构会震 |
| ③ 慢速退出到释放 | 必须让开关**完全释放**，否则第二次触发点不准 | 开关停在临界位置，重复性极差 |
| ④ 立即 Halt | 释放瞬间速度只有 1 mm/s，硬停不会丢步 | 减速会多走 0.05 mm，白等 |
| ⑤ 1 mm/s 二次趋近 | **核心**：触发点离散性与速度正相关，低速趋近把离散压到最小 | 直接用 10 mm/s 触发，10 次极差能到 0.1 mm 以上，指标 4（≤0.05 mm）过不了 |
| ⑤ 触发时 `position = 0` | 把当前物理点定义为坐标原点 | 坐标与机械脱钩，绝对定位失去意义 |
| ⑥ 退到 +2 mm | 让机构离开开关，避免开机就压在限位上 | 下次回零第一步被"已在限位"挡住 |

### 4.3 触发瞬间为什么用 Halt 而不是 Stop

1 mm/s 时，一个 1 ms 规划周期只走 1 µm。此时 `Halt` 的直接效果是"停在下发那一拍的触发点上"，而 `Stop` 会再往前滑 2~3 个脉冲（约 5~10 µm）。
看起来都不大，但指标要求 10 次回零极差 ≤ 0.05 mm，把 10 µm 的系统性偏移去掉，余量立刻多一倍。

### 4.4 超时保护

```c
if (m->home_timer > STEPPER_HOME_TIMEOUT_MS)     // 20000 ms
{
    Stepper_Halt(id);
    m->home_state = STEPPER_HOME_FAIL;
    m->alarm = 1;  m->alarm_code = STEPPER_ALM_HOME;
}
```

每个阶段独立计时（切阶段时 `home_timer = 0`）。没有这个保护，开关线断了电机就会一直往负方向撞，把机构顶坏。

### 4.5 回零期间限位不报警

`Stepper_Begin()` 里判断：

```c
homing = (m->home_state != STEPPER_HOME_NONE && ... );
if (s_limits_enabled && !homing)     // 回零流程跳过限位封锁
{
    if (direction < 0 && Stepper_LimitNegActive(m)) return 0;
    ...
}
```

否则回零第一次往负限位走就会被自己挡住。

### 4.6 现在为什么还没打开

`main.c` 里：

```c
#define LIMITS_ENABLE   0    // 限位：关（等确认开关极性）
#define HOME_ON_BOOT    0    // 上电回零：关
```

四个限位输入当前读成 `LIM=1111`（全高）。如果开关实际是"遮挡=低电平"，打开后控制器会以为四个限位全部触发，回零第一步就动不了。
所以顺序必须是：先跑 `host/check_limits.py` 确认极性 → 再改这两个宏。

## 5. F5 硬限位 / 急停：中断里只做一件事

### 5.1 为什么必须用外部中断

限位是最后一道防线，等主循环轮询到已经晚了（主循环可能正在 `HAL_Delay` 或拼字符串）。
所以四个限位 + 急停全部配成 EXTI，中断里**只做"封脉冲 + 置报警"两件事**，绝不做减速、绝不打串口：

```c
/* stepper.c:624 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    switch (GPIO_Pin)
    {
    case X_LIMIT_NEG_Pin:  Stepper_OnLimitHit(STEPPER_X, -1); break;
    case X_LIMIT_POS_Pin:  Stepper_OnLimitHit(STEPPER_X, +1); break;
    case Y_LIMIT_NEG_Pin:  Stepper_OnLimitHit(STEPPER_Y, -1); break;
    case Y_LIMIT_POS_Pin:  Stepper_OnLimitHit(STEPPER_Y, +1); break;
    case EMERGENCY_STOP_Pin: Stepper_OnEmergencyStop();       break;
    }
}
```

`Stepper_OnLimitHit()` 内部：`Stepper_Halt(id)` → `alarm = 1` → `alarm_code = 1`（限位）。
之后 `Stepper_Planner_1ms` 看到 `alarm` 会强制 `increment = 0`，`Stepper_Begin()` 会拒绝任何新指令，必须 `RESET` 才能恢复。

### 5.2 中断优先级

当前 `TIM2` 抢占优先级是 0。接上真实限位后**必须把 TIM2 降到 1，把 0 留给 EXTI**。
优先级相同的情况下，如果 TIM2 正在执行，EXTI 要等它退出来才响应——最多 20 µs，虽然也能接受，但既然能配就别留隐患。

### 5.3 限位报警与急停报警的区别

| | 限位（code=1） | 急停（code=2） |
|---|---|---|
| 触发 | 单轴撞到行程开关 | 按下急停按钮 |
| 影响范围 | 只锁该轴 | **两轴全停** |
| `homed` | 保留 | **清零**（位置不可信，必须重新回零） |
| 恢复 | 反方向退出 + `RESET` | 松开急停 + `RESET` + 重新回零 |

急停后清零 `homed` 是必须的：急停可能发生在运动中，实际位置与脉冲计数不再一致，不清零会导致软限位算错。

## 6. F6 软限位：为什么回零后才生效

软限位在 `Stepper_Begin()` 和 `Stepper_MoveAbs()` 里判断目标位置：

```c
if (m->homed)                       // 只有回零后坐标才有物理意义
{
    float mm = (float)(m->position + nx) * m->delta;
    if (mm < m->sl_min || mm > m->sl_max) return 0;   // 拒绝，电机不动
}
```

**为什么必须回零**：没回零时 `position` 是从上电开始的累计脉冲数，和机械位置没有任何对应关系，谈"越界"没有意义。

**和硬限位的层次关系**：

```
        软件层  软限位：目标越界 → 指令根本不执行（电机不动，回 ERR,4）
        ─────────────────────────────────────────────
        物理层  硬限位：真撞上 → 中断封脉冲 + 报警锁定（要人工复位）
```

默认值 `SLMIN=0 / SLMAX=240`（`stepper.h`）。240 是 X 轴有效行程，0 对应回零后的机械零点。建议留 3~5 mm 余量，不要贴着硬限位设。

## 7. F8 通信超时：一个真实事故的完整复盘

### 7.1 现象

联调时发 `MOV X10 F20`，电机**跑了 67 mm 还不停**，位置一路涨到 97 mm。看起来像"运动控制完全失控"。

### 7.2 定位过程

1. 先排除"位置显示错误"：30.138 mm ↔ 9644 脉冲，换算一致 → 是真跑了那么远；
2. 复位后静止 3 s，位置不变 → 不是干扰导致的误脉冲；
3. 发一次 `MOV X10`，按 50 ms 采样状态 → **一直匀速跑，永不进入 IDLE** → 到位判据失效；
4. 查所有能改 `target` 的地方 → 只有 `Stepper_Stop()`；
5. 查谁在反复调 `Stepper_Stop()` → 规划节拍里的 F8 超时分支。

### 7.3 根因

```c
/* 错误版本 */
if (s_host_seen && (HAL_GetTick() - s_last_rx_ms) > 500)
{
    if (有轴在动) Stepper_StopAll();     // ← 每 1 ms 执行一次！
}
```

而 `Stepper_Stop()` 的语义是"把目标改成当前位置 + 制动距离"。
每毫秒调一次 → 目标永远跟着位置往前跑 → **永远追不上** → 无限匀速巡航。

### 7.4 修法

```c
/* stepper.c:1113 修复版 */
if (s_host_seen && !s_comm_trip &&
    (HAL_GetTick() - s_last_rx_ms) > STEPPER_COMM_TIMEOUT_MS)
{
    s_comm_trip = 1;          // 一次性标志
    s_comm_lost = 1;
    Stepper_StopAll();
}
```

`Stepper_NoteHostMessage()` 里清 `s_comm_trip`，这样收到新报文后保护可以重新生效。

### 7.5 教训（写报告可以引用）

- **幂等的动作可以重复调用，非幂等的动作必须加一次性标志**。`Stop` 不是幂等的（每次都会重新算目标）。
- 保护逻辑要问一句："这个函数在 1 ms 里被调 1000 次，会发生什么？"
- 掉线保护的正确语义是"**停一次**"，不是"**一直停**"。

## 8. F10/F12：状态上报与运动记录

### 8.1 状态帧

每 100 ms 一条，由 `Protocol_Poll()` 的定时分支发出：

```
<ST X=12.500,25.00,RUN,H1 Y=0.000,0.00,IDLE,H0 LIM=0000 ALM=0>
     └─位置mm 速度mm/s 状态 已回零         限位 X-X+Y-Y+  报警码
```

设计要点：
- **固定 4 位小数/2 位小数**，上位机不用猜格式，直接 `split`
- 位置用 `%.3f`（3.125 µm 分辨率下 3 位小数够了），速度 `%.2f`
- `LIM` 是四位位图，从低到高 `X- X+ Y- Y+`
- 一条 144 字节栈缓冲拼完一次性发，避免多次 `printf` 打断

### 8.2 运动记录（F12）

采集：在 1 ms 规划节拍里，每轴算一次"这一毫秒走了几个脉冲"，存进 `uint16_t` 数组：

```c
/* stepper.c:1053 Stepper_TraceSample() 核心 */
int32_t d = m->position - m->tr_last;
m->tr_last = m->position;
s_trace_buf[m->tr_n++] = (uint16_t)(d >= 0 ? d : -d);
```

为什么存**增量**而不是绝对位置：
- 增量范围 0~几百，`uint16_t` 够；绝对位置要到 10^6，得用 4 字节
- 3000 点 × 2 字节 = 6 KB，20 KB RAM 装得下（实测 RAM 占用 8.4 KB）

上传：`DUMP` 时先发帧头，再逐行发整数，最后发结束标记：

```
<TR X N=345 DT=1 STOP=-1>
<数字>
...
<TREND>
```

`STOP=-1` 表示本次记录没有收到停止指令；如果中途 `STOP`，`Stepper_TraceMarkStop()` 会把当前序号写进去，上位机就能在曲线上标出"停止发生在第几个点"。

### 8.3 上位机怎么把它变成曲线

```python
# protocol.py:286 compute_trace()
# 增量(脉冲) → 速度(mm/s)：v = Δ · δ / dt
v = [d * delta_mm / (dt_ms / 1000.0) for d in deltas]
# 位置：前缀和
x = [sum(deltas[:i+1]) * delta_mm for i in range(len(deltas))]
```

加速度不是"取两点差分"（噪声太大），而是**对加速段做最小二乘线性拟合**：

```python
# protocol.py:304 fit_acceleration()
num = sum((t - mt) * (v - mv) for t, v in zip(ts, vs))
den = sum((t - mt) ** 2 for t in ts)
return num / den
```

这就是报告里"加速段线性拟合 a = 200.3 mm/s²（设定 200，误差 0.15%）"的来源，对应任务书指标 6。

## 9. 两轴联动（挑战要求②）

### 9.1 核心思想：不写插补器，只按比例分速度

```
L  = √(ΔX² + ΔY²)          轨迹长度
kx = |ΔX| / L,  ky = |ΔY| / L
vx = F · kx,    vy = F · ky   （F = 合成进给速度）
ax = A · kx,    ay = A · ky   （A = 公共加速度）
```

### 9.2 为什么轨迹是严格直线

两轴都从 0 开始加速，加速度分别是 `A·kx` 和 `A·ky`，所以任意时刻：

```
vx(t) / vy(t) = (A·kx·t) / (A·ky·t) = kx/ky = |ΔX|/|ΔY|   （常数）
```

速度比恒定 → 位移比恒定 → 轨迹是通过起点、斜率为 `ΔY/ΔX` 的直线。

### 9.3 为什么同时到达

- 加速时间：`t_acc = vx/(A·kx) = F/A`，两轴相同
- 匀速时间：`t_cr = (剩余)/v`，两轴分配的剩余距离与速度同比例，也相同
- 减速时间：同理相同

三段都相同 → 总时间相同 → 同时到达。实测两轴在同一帧状态里同时变 `IDLE`。

### 9.4 三个实现细节（都在 `Stepper_MoveLine` 里）

**① 用整数脉冲反算比例**

```c
lx = dx / mx->delta;  nx = round(lx);      // 先定下"实际要走几个脉冲"
lx = fabsf((float)nx * mx->delta);         // 再用整数脉冲反算真实位移
```

如果直接用浮点 `dx` 算比例，四舍五入后某一轴可能少走 1 个脉冲，导致另一个轴先到、斜线末端出现小折角。

**② 公共加速度取最小值**

```c
a = 1e9;
if (kx > 0) a = min(a, mx->acc_cmd / kx);
if (ky > 0) a = min(a, my->acc_cmd / ky);
```

保证 `A·kx ≤ 该轴设定加速度`，不会因为联动把某一轴逼到丢步。

**③ 超 Vmax 时整体降速，不能单独降一轴**

```c
if (v * kx > mx->vmax) v = mx->vmax / kx;
if (v * ky > my->vmax) v = my->vmax / ky;
```

比例一旦改动，轨迹就会拐弯。所以只能整体降 `F`，保持 `kx:ky` 不变。

### 9.5 参数污染问题

`Stepper_Begin()` 每次启动都会 `m->acc = m->acc_cmd` 恢复用户设定值，`MoveLine` 在其中之后再覆盖成缩放值。这样联动结束后 `GET X` 读到的 `ACC` 仍是 200（实测验证），不会因为联动过一次就变成 141.4。

## 10. 上位机架构：三层为什么这么分

### 10.1 分层与依赖方向

```
ui_main.py     界面：按钮、状态机、提示框
    ↓ 只用
protocol.py    纯函数：打包指令、解析报文、算曲线   ← 可以脱离界面单测
    ↓ 只用
serial_link.py 串口线程：收发字节、断线检测
```

反向依赖是禁止的：`protocol.py` 里不允许出现 `QWidget`，`serial_link.py` 里不允许出现业务逻辑。
好处：`selftest.py` 能不开界面直接测 39 项；换 UI 框架（PyQt5 → PySide6）只改最后一层。

### 10.2 为什么串口要放在 QThread

`serial.read()` 是阻塞调用。放在主线程会导致界面卡顿（点按钮没反应、窗口拖不动）。
`SerialWorker(QThread)` 里循环读，读到一行就 `emit line_received(str, float)`；Qt 自动用队列连接把信号投递回主线程，所以界面槽函数里可以安全操作控件。

发送方向则相反：主线程 `send()` 把字符串塞进队列，工作线程取出写入——**串口对象只在工作线程里被访问**，避免多线程同时读写。

### 10.3 心跳与超时的时间关系

```
上位机：每 200 ms 发一次 PING          （config.HEARTBEAT_MS = 200）
下位机：500 ms 收不到任何报文 → 减速停 （STEPPER_COMM_TIMEOUT_MS = 500）
```

200 < 500，留了 300 ms 余量吸收串口抖动。如果上位机卡死（比如断点调试），500 ms 后电机自动停——这是安全设计，不是 bug。

### 10.4 4.3.2 状态规则怎么落地

任务书要求"报警禁运动、运动中该轴禁操作但另一轴可用、未回零禁绝对定位、通信中断禁用全部"。实现集中在 `_refresh_status_widgets()` 一处：

```python
busy_x = st.x.busy
self.axis_x.set_state(connected and not alarm, busy_x)
self.axis_y.set_state(connected and not alarm, busy_y)
self.line.set_state(connected and not alarm, busy_x or busy_y)
```

「另一轴可用」自然成立：每张卡片的使能只看自己轴的 `busy`。
「未回零禁绝对定位」在 `AxisPanel` 内部判断 `st.homed`。
「通信中断禁用全部」由 `conn_state != CONN_OK` 一次性关掉。

**规则只写在一个地方**，避免按钮状态散落各处、改一处漏一处。

### 10.5 图表为什么自绘

`trace_plot.py` 用 `QPainter` 画双栏（上：v-t，下：x-t），没有用 matplotlib：
- matplotlib 打包 40 MB+，答辩现场拷过去容易缺依赖
- 3000 点重绘，`QPainter` 在 60 fps 下毫无压力
- 需要标"停止点"竖线、显示拟合值，自绘反而更自由

### 10.6 一个必须记住的 Qt 陷阱（真实事故）

`MainWindow` 里曾经同时存在：

```python
def on_line(self, line: str, ts_ms: float):   # 串口接收
def on_line(self, dx: float, dy: float, feed: float):  # 联动按钮
```

Python 后定义的覆盖先定义的。`connect()` 不会报错，运行到第一帧状态上报就抛
`TypeError: on_line() missing 1 required positional argument: 'feed'`，
结果是**界面状态永远不刷新、所有按钮永远灰**——而且错误只在后台 stderr 里刷屏，界面上完全看不出来。

修法：联动函数改名 `on_line_move`。
教训：
1. 加新方法前 `grep -n "def 方法名"`；
2. Qt 的 `connect` 是弱类型，参数不匹配不会在连接时报错，只会在运行时抛；
3. 界面"全部变灰"优先怀疑**信号槽异常**，而不是"没连上"。

## 13. 公式与常量速查

```
δ  = 导程 / PPR                       脉冲当量 (mm/pulse)
K  = v · 2³² / (δ · ft)               速度 → 相位增量
f  = K · ft / 2³²                     相位增量 → 脉冲频率 (Hz)
v  = f · δ                            脉冲频率 → 速度 (mm/s)
N  = L / δ                            行程 → 脉冲数
v_max = 25000 · δ                     由脉宽占 2 拍决定的最高速
v_brake = √(2·a·s)                    制动速度上限
```
