## 0. 先建立调用关系图

### 0.1 下位机三个中断 + 一个主循环

```
            ┌──────────────────────────────────────────────┐
   50 kHz   │ TIM2 更新中断  → Stepper_TIM_Callback()      │  ← 只干"发脉冲"一件事
            │                   ├ Stepper_Axis_Tick(X)     │     执行时间 < 3 µs
            │                   └ Stepper_Axis_Tick(Y)     │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
    1 kHz   │ SysTick 中断   → Stepper_Planner_1ms()       │  ← 只干"算速度"一件事
            │                   ├ 通信超时判断             │     执行时间 ~8 µs
            │                   ├ Stepper_TraceSample      │
            │                   ├ Stepper_HomeTick         │
            │                   └ 梯形/三角形速度 → K      │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
   事件驱动 │ EXTI 中断      → HAL_GPIO_EXTI_Callback()    │  ← 只干"封脉冲"一件事
            │                   ├ Stepper_OnLimitHit       │     执行时间 < 2 µs
            │                   └ Stepper_EmergencyStop    │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
   随时     │ 串口接收中断   → HAL_UART_RxCpltCallback()   │  ← 只干"塞 1 个字节"
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
   主循环   │ while(1) → Protocol_Poll()                   │  ← 组行、分派、100 ms 上报
            └──────────────────────────────────────────────┘
```

四条执行流之间**只通过 `StepperAxis` 结构体里的变量通信**，没有任何函数调用跨流。
这就是为什么所有可被中断打断的共享变量都必须声明 `volatile`。

### 0.2 一次"按钮点动"要穿过多少层

```
上位机按钮 → cmd_jog() → "JOG X+ F20\r\n"
   ↓ USB 虚拟串口
USART1 接收中断 → s_rx_buf 环形缓冲（1 字节）
   ↓ 主循环
Protocol_Poll → Dispatch → CmdJog → Stepper_Start
   ↓ 设置 target/v_cmd/state，方向引脚
1 ms 规划 → v_plan += a·T → Stepper_SpeedToIncrement → increment
   ↓
50 kHz 节拍 → phase += increment → 溢出 → STEP 引脚拉低 20 µs → position ±1
   ↓
100 ms 上报 → <ST X=1.234,20.00,RUN,H1 ...>
   ↓
上位机 on_line → parse_status → 刷新界面
```

这条链路你必须在脑子里能一口气画出来，答辩时被问"按下按钮后发生了什么"就是考这个。

## 1. 数据结构：`StepperAxis`

```c
typedef struct {
    /* ① 引脚 */        step_port, step_pin, dir_port, dir_pin,
                        lim_neg_port, lim_neg_pin, lim_pos_port, lim_pos_pin
    /* ② 参数 */        acc, acc_cmd, vmax, delta, k_gain,
                        home_fast, home_slow, sl_min, sl_max, lead, ppr, dir_inv
    /* ③ 记录 */        tr_on, tr_n, tr_last
    /* ④ 脉冲层 */      phase, increment, pulse_active, start_wait
    /* ⑤ 规划层 */      position, target, v_cmd, v_plan, direction, state
    /* ⑥ 回零报警 */    home_state, home_timer, homed, alarm, alarm_code
} StepperAxis;

static StepperAxis motor[STEPPER_NUM];      // 两轴共用一套代码（F11）
```

### 1.1 五个必须分清的"速度"

| 变量 | 含义 | 谁写 | 谁读 |
|---|---|---|---|
| `v_cmd` | 用户要的速度（目标巡航速度） | 主循环（Begin） | 规划层 |
| `v_plan` | 当前规划速度（≥0，是"大小"） | 规划层 | 规划层、`GetSpeedMM` |
| `increment` | 速度换算成的相位增量 K | 规划层 | 50 kHz 节拍 |
| `position` | 已发出的脉冲数（指令位置） | 50 kHz 节拍 | 所有人 |
| `target` | 要到达的脉冲数 | 主循环 / Stop / 规划层不改 | 规划层、节拍层比较 |

**为什么 `v_plan` 不带符号**：方向由 `direction` 单独表示。
速度大小和方向分开，`√(2as)` 里就不用管符号，少一堆 `if`。
对外输出时才合成：`Stepper_GetSpeedMM` 返回 `v_plan * direction`。

**为什么 `position` 只有脉冲层能写**：位置是"实际发了多少个脉冲"的账本，
任何人（包括上位机、回零状态机）都不许直接改成"我以为的位置"。
唯一例外是回零第 ④ 步 `m->position = 0`——因为那一刻开关触发了，物理位置是已知的。

### 1.2 `acc` 和 `acc_cmd` 为什么要两个

`acc_cmd` 是用户在 `SET ACC=200` 里写的**设定值**；
`acc` 是**本次运动实际生效值**。联动时 `Stepper_MoveLine` 会把 `acc` 改成 `a*kx`
（比如 200×0.707=141.4），但用户设定值不能被污染，下次单轴运动还要用 200。
`Stepper_Begin` 第 212 行 `m->acc = m->acc_cmd;` 就是"每次启动先恢复设定值"。

这是新手最容易写的 bug：只留一个 `acc`，联动一次之后单轴加速度就再也不对了。

### 1.3 哪些必须 `volatile`

判断标准：**这个变量会被中断改，而在主循环里被读**，或者反之。

- `phase / increment / position / pulse_active / start_wait`：50 kHz 中断写，主循环读 → volatile
- `state / v_plan / target / direction`：双向都写 → volatile
- `home_state / home_timer`：1 ms 中断写，主循环读 → volatile
- `delta / k_gain / ppr / lead`：只在主循环写，中断读 → 也应 volatile（当前代码里未加，
  但改写只发生在 IDLE 时，实际安全；如果要在运动中改参数必须加）

`volatile` **不保证原子性**。所以代码里凡是"读-改-写"跨流的地方都用 `__disable_irq()` 包住
（`Stepper_Begin`、`Stepper_Stop`、`Stepper_Halt`、`Stepper_ResetAlarm`、`Stepper_TraceArm`）。

## 2. `stepper.c` 逐函数

### 2.1 内部工具（6 个）

#### `Stepper_Recompute(StepperAxis *m)` —— 第 124 行

**【作用】** 机械参数变了以后，重算脉冲当量 δ 和速度增益 `k_gain`。这两个数必须成对更新。

```c
m->delta  = m->lead / (float)m->ppr;                        // 0.003125 mm
m->k_gain = 4294967296.0f / (m->delta * (float)STEPPER_TICK_HZ);
```

**【逐行】**
- δ = 导程 ÷ 每转脉冲数。5 mm / 1600 = 0.003125 mm。
- `k_gain` 是"1 mm/s 对应多少相位增量"：`K = v · k_gain`。
  推导：f = v/δ（脉冲频率），K = f·2³²/ft = v·2³²/(δ·ft)。
- 数值：5 mm/1600 时 `k_gain = 4294967296/(0.003125×50000) = 2.7488×10⁷`。

**【坑】**
1. `4294967296.0f` 超出 float 的 24 位精度（2³² 需要 33 位），实际存成 4294967296.0，
   误差在 1e-7 量级。可以接受，但**不要**用 `float` 去算更精细的东西（比如位置累加，那里用的全是 int32）。
2. 这个函数**不检查 `ppr==0`**，第 126 行虽然有一句兜底，但只在 `Stepper_Recompute` 内部生效；
   `Stepper_SetPPR` 已经做了查表，正常不会传 0。

**【考点】** 为什么 K 是这个公式？——因为相位累加器每拍加 K，累加满 2³² 溢出一次，
溢出的平均频率就是 `K·ft / 2³²`，令它等于 `v/δ` 就得到 K。

---

#### `Stepper_ApplyDirection(m, direction)` —— 第 133 行

**【作用】** 把逻辑方向（+1/-1）变成 DIR 引脚电平。

```c
level = (direction > 0) ? 1 : 0;
if (m->dir_inv) level = !level;
HAL_GPIO_WritePin(m->dir_port, m->dir_pin, level ? SET : RESET);
```

**【逐行】** 三步：算电平 → 按 `dir_inv` 取反（现场电机反接时的软件纠正）→ 写引脚。

**【坑】** 只在 `Stepper_Begin` 里调用，此时 `v_plan==0`、`increment==0`，绝对没有脉冲在发。
**千万不要在运动中改方向**：驱动器对方向信号的建立时间有要求（通常 5 µs），
而且改方向瞬间如果还有残余脉冲，机械上会丢步。`Stepper_SetDirInv` 也因此限制 `state==IDLE`。

---

#### `Stepper_LimitNegActive(m)` / `Stepper_LimitPosActive(m)` —— 第 148 / 153 行

**【作用】** 读限位开关，返回 1 = 遮挡/触发。

```c
return (HAL_GPIO_ReadPin(port, pin) == GPIO_PIN_SET) ? 1u : 0u;
```

**【逐行】** 一行：高电平 = 触发。这不是随便定的——FML-V2 光电开关是**常闭（NC）输出**：
未遮挡时内部三极管导通把引脚拉低，遮挡时断开、靠 MCU 内部上拉拉高。
这种接法是**故障安全**的：线断了 = 高电平 = 触发 = 停车。

**【坑】** 如果你的开关是 NPN 常开型，逻辑正好相反，回零会立刻"一启动就到位"。
调试方法：万用表量未遮挡时的电平，或看 `<ST ... LIM=xxxx>` 的 4 个位。

**【考点】** 为什么选常闭而不是常开？——断线保护。报告 4.5 节可以写这一点。

---

#### `Stepper_SpeedToIncrement(m, v)` —— 第 159 行

**【作用】** 速度（mm/s）→ 相位增量 K。

```c
if (v <= 0.0f) return 0;
k = v * m->k_gain;
if (k > (float)INCREMENT_MAX) k = (float)INCREMENT_MAX;
return (uint32_t)k;
```

**【逐行】**
- `v<=0` 直接返回 0：停止时不累加，避免负速度导致相位倒退（倒退会变成反向脉冲）。
- 钳位到 `0x7FFFFFFF`（2³¹−1）：**这是整个脉冲方案的核心约束**。
  若 K > 2³¹，一拍内相位可能溢出 2 次，但代码只检测"变小了"一次，
  就会漏掉一个脉冲 → 频率失控。钳到 2³¹ 保证**每拍最多溢出一次** → 输出频率上限 25 kHz。
- 强转 `(uint32_t)k` 是截断不是四舍五入，误差 < 1 个 K，对应频率误差 < 0.04 Hz，无所谓。

**【坑】** 有人会把钳位写成 `0xFFFFFFFF`，觉得"让它能跑更快"。结果是过了 25 kHz
位置计数开始丢，定长运动永远到不了目标（因为 `position` 追不上 `target`... 实际上是
`position` 跳得太快越过 target，`==` 判断永远不成立 → 电机不停）。这就是"能转但停不下来"的经典故障。

---

#### `Stepper_Begin(m, direction, target, speed)` —— 第 174 行

**【作用】** 所有运动（JOG / MOV / MOVA / LINE / 回零的每一段）的**唯一启动入口**。
把"能不能动"检查完，然后一次性把状态摆好。

**【逐行】**
1. 第 179 行：判断是否处于回零流程中（`homing` 标志）。
2. 第 185 行：若限位已启用且不在回零 → **禁止朝限位方向运动**。
   注意这里只判断"当前是否已经压在限位上"，即"已经撞了就不许再往那边走"，
   真正的动态拦截靠 EXTI 中断。
3. 第 193 行 `__disable_irq()`：进入临界区。
4. 第 195 行：再判一次 `state != IDLE || alarm`。为什么要判两次？
   前面第 185 行的检查是普通代码，可能被中断打断；这里关中断后判的才是权威值。
   **这是典型的 TOCTOU（检查后使用）防护**。
5. 第 201-207 行：写方向 → 清 `increment` → 清 `phase` → 清 `pulse_active`
   → `start_wait = 50`（50 拍 × 20 µs = 1 ms 方向建立时间）。
6. 第 209-213 行：写 `target / v_cmd / v_plan=0 / acc=acc_cmd / state=ACC`。
7. 第 215 行 `__enable_irq()`，返回 1。

**【坑】**
1. `m->acc = m->acc_cmd;` 必须在这里做。联动时 `MoveLine` 随后覆盖成 `a*kx`。
2. `start_wait = 50` 是两轴"同时启动"的关键（见 `MoveLine`）。如果改成 0，
   两轴会因为主循环里连续两次函数调用的时间差（几微秒，但相对 20 µs 节拍不确定）
   而错开一拍，长距离斜线末端会看到 0.003 mm 的台阶。
3. 这里的 `__disable_irq()` 会屏蔽所有中断包括串口。临界区里只有十几条指令（<2 µs），
   不会丢串口字节（115200 下 1 字节 87 µs）。**但如果以后在临界区里加 `printf` 或浮点运算就要出事**。

**【考点】** 为什么启动时 `v_plan` 要归零而不是接着上次的速度？——每次运动都从静止开始，
默认电机已经停住。连续插补（项目二）才需要"速度衔接"，那时要改这里。

### 2.2 初始化

#### `Stepper_Init(void)` —— 第 222 行

**【作用】** 上电调用一次：绑定引脚、清零状态、装默认参数、把 STEP 置高（关断）。

**【逐行】**
- 第 224-240 行：把 `main.h` 里 CubeMX 生成的引脚宏（`X_STEP_GPIO_Port` 等）抄进轴对象。
  这样后面所有函数都不直接引用引脚宏，只认 `m->step_port/step_pin` → **两轴共用一套代码**。
- 第 242-280 行：循环清零 + 装默认值。
- 第 276 行：`Stepper_Recompute` 算 δ 和 k_gain。
- 第 279 行：`HAL_GPIO_WritePin(step, SET)`。**共阳接法下高电平 = 光耦关断**，
  上电先给高电平，防止复位过程中引脚浮空导致驱动器收到假脉冲而"抖一下"。

**【坑】** 顺序不能反：`MX_GPIO_Init()` 必须在 `Stepper_Init()` 之前，
`Stepper_Init` 里才敢写引脚。`main.c` 第 130-135 行的顺序是对的。
`HAL_TIM_Base_Start_IT(&htim2)` 要在 `Stepper_Init` 之后，否则第一拍中断里
`motor[]` 还是全 0，`increment=0` 倒也无害，但 `delta=0` 会让后续除法出 NaN。

### 2.3 运动指令（4 个入口 + 2 个停止）

#### `Stepper_Start(id, direction, speed)` —— 第 286 行｜**点动 JOG**

**【作用】** 连续运动。目标设到 300 mm 之外，靠 `Stepper_Stop` 的减速曲线收尾。

**【逐行】**
1. 第 291-298 行：三个检查——轴号、方向必须 ±1、速度在 `[0.1, vmax]`。
2. 第 300 行：`span = 300 mm / δ` → 约 96000 个脉冲。
3. 第 301-304 行：`target = position ± span`。
4. 第 307-326 行：若已回零，用软限位把目标**钳在边界上**（不是拒绝）：
   - 已经在边界外 → 返回 0（不许再往那边走）
   - 目标越过边界 → `target = 边界`，能走到边界就停
   这样点动可以放心长按，到软限位自动停。
5. 第 328 行：交给 `Stepper_Begin`。

**【坑】** 为什么不判断 `target` 是否超出 int32？96000 远小于 2³¹，安全。
但如果把 `JOG_LIMIT_MM` 改成 100000 mm，`span = 3.2e7`，加上 position 就可能溢出。
**【考点】** 点动为什么不用"速度模式"（一直发固定频率）而用"超长目标 + 减速停"？
——因为这样点动和定长共用同一套规划与停止逻辑，代码只有一份，行为一致。

---

#### `Stepper_MoveRel(id, distance_mm, speed)` —— 第 334 行｜**定长 MOV**

**【作用】** 走固定距离，正负表示方向。

**【逐行】**
1. 第 347-351 行：速度范围、必须 IDLE。
2. 第 354-355 行：`nd = L/δ`，然后**四舍五入**：
   `n = (int32_t)(nd + (nd>=0 ? 0.5 : -0.5))`。负数的处理必须单独写，
   直接 `+0.5` 会让 −3.6 变成 −3（错的，应该 −4）。
3. 第 357 行：`n == 0` 返回 0。一个脉冲当量 0.003125 mm，比这更小的位移走不了。
   命令行的表现就是 `MOV X0.001` 回 `ERR,4`。
4. 第 360 行：`target = position + n`（相对）。
5. 第 363-368 行：已回零 → 用 **mm** 比较软限位（先转 mm 再比，避免脉冲取整误差累积）。
6. 第 370 行：方向由 `n` 的符号决定，交给 Begin。

**【坑】** 如果 `target` 恰好等于 `position`（`n==0` 已拦），如果电机已经在 target 上，
`Begin` 会把 state 设成 ACC，第一毫秒 `remain=0 → v_brake=0 → v_plan=0`，
`increment=0`，状态永远停在 ACC，`IsBusy` 一直为 1 → **界面卡在"运行中"，再也发不出指令**。
`MoveRel` 用 `n==0` 挡掉了这种情况；`MoveAbs` 用第 400 行 `if (n == m->position) return 0;` 挡掉。
**这两个判断是必须的，不是多余的。**

---

#### `Stepper_MoveAbs(id, pos_mm, speed)` —— 第 376 行｜**绝对定位 MOVA**

**【作用】** 走到机械坐标 `pos_mm`（回零后的坐标系）。

**【逐行】**
1. 第 388 行：`!m->homed` 直接拒绝 → 协议层回 `ERR,3`（未回零）。
2. 第 394 行：目标本身必须在软限位内（这是"目标合法性"，不是"路径合法性"）。
3. 第 397-398 行：mm → 脉冲，四舍五入同上。
4. 第 400 行：已经在目标上 → 返回 0。
5. 第 405 行：方向由 `target > position` 决定。

**【为什么绝对坐标就等于脉冲数】** 回零第 ④ 步把 `position = 0`，
第 ⑤ 步退 +2 mm 后 `position = 640`，此后 `position·δ` 就是"离机械零点多少 mm"。
坐标系原点 = 机械零点，所以 `target = pos_mm/δ` 不需要加偏移量。

**【考点】** 软限位为什么在 MOVA 里也要判？——因为 `SET SLMAX` 是运行时可改的，
用户可能把 SLMAX 改小到当前位置以内，此时 MOVA 到旧坐标就危险了。

---

#### `Stepper_MoveLine(dx, dy, feed)` —— 第 422 行｜**两轴联动（挑战②）**

**【作用】** 一条指令让两轴同时启动、同时到达，轨迹是严格直线。全文最长的一个函数（88 行）。

**【逐行】**

```c
// ① 前置检查（429-436）
if (mx->state != IDLE || my->state != IDLE) return 0;   // 任一轴忙 → 拒绝
if (mx->alarm || my->alarm) return 0;
if (feed < VMIN || feed > 200.0f) return 0;
```

```c
// ② 位移 → 整数脉冲，再反算实际位移（438-452）
lx = dx / mx->delta;  nx = round(lx);
ly = dy / my->delta;  ny = round(ly);
if (nx == 0 && ny == 0) return 0;
lx = fabsf(nx * mx->delta);      // 注意：用的是取整后的脉冲反算
ly = fabsf(ny * my->delta);
len = sqrtf(lx*lx + ly*ly);
```

**为什么反过来用脉冲算长度**：如果直接用用户给的 `dx/dy` 算比例，
比例是 `dx/dy`，但实际走的是 `nx·δ / ny·δ`，两者差一个取整误差。
0.5 个脉冲当量的比例误差，在 200 mm 行程上会让末端出现 0.0015 mm 的偏差，
而两轴"同时到达"的性质一旦被破坏，晚到的那一轴会在末端多走一小段斜线。
用取整后的脉冲算，`kx:ky` 与"最终发出的脉冲数之比"严格相等 → 两轴必然同时到达。

```c
// ③ 软限位预判（457-469）：任一轴越界，整条斜线都不执行
if (mx->homed) { mm = (position+nx)*δ; if (mm<sl_min||mm>sl_max) return 0; }
// 注意：这里只判终点，不判路径。直线路径的极值一定在端点上（行程是单调的），所以够用。
```

```c
// ④ 速度分配（471-483）
v = feed;
if (kx > 0 && v*kx > mx->vmax) v = mx->vmax / kx;   // 某轴要超速 → 整体降速
if (ky > 0 && v*ky > my->vmax) v = my->vmax / ky;
vx = v*kx;  vy = v*ky;
if ((nx!=0 && vx<VMIN) || (ny!=0 && vy<VMIN)) return 0;
```

**为什么不是"把超速那轴单独限到 vmax"**：那样比例就变了，轨迹会拐弯。
只能整体降速——这也是真实 CNC 机床的行为（进给倍率）。

**为什么低速要拒绝**：`v=0.1 mm/s`、`k=0.01` 时 `vx=0.001 mm/s`，
对应 K≈27000，一个脉冲要 159 秒；期间如果目标只剩几个脉冲，`√(2as)` 会算出
负的…不会，但位置分辨率已经差到没意义。宁可报错，也不给"看起来在动其实在爬"的结果。

```c
// ⑤ 公共加速度（485-488）
a = 1e9;
if (kx>0) a = min(a, mx->acc_cmd / kx);
if (ky>0) a = min(a, my->acc_cmd / ky);
```

**为什么要取 min**：`ax = a·kx` 必须 ≤ `acc_cmd_x`。若 X 轴设定 100、Y 轴设定 500，
`kx=ky=0.707`，则 X 允许 `a ≤ 141`、Y 允许 `a ≤ 707`，取 141 → Y 实际只用到 100。
反过来若取 Y 的 707，X 就会以 500 加速，超出用户设定，可能丢步。

```c
// ⑥ 依次启动（493-502）
if (nx!=0 && !Stepper_Begin(mx, sign(nx), tx, vx)) return 0;
if (ny!=0 && !Stepper_Begin(my, sign(ny), ty, vy)) { Stepper_Halt(X); return 0; }
```

**"同时启动"到底靠什么**：`Stepper_Begin` 把 `start_wait` 都设成 50 拍。
两轴都在 50 kHz 节拍里倒数，第 51 拍同时进入相位累加。
主循环里两次调用的时间差（几微秒）完全被这 1 ms 的等待吸收掉了。
**这就是为什么两轴的运动，`start_wait` 必须相同。**

**回滚**：Y 启动失败（比如 Y 报警）时，X 已经开始等了，必须 `Halt(X)` 撤掉，
否则会走出"半条斜线"——X 自己走到位，Y 没动。

```c
// ⑦ 覆盖加速度（504-506）
if (nx!=0) mx->acc = a * kx;
if (ny!=0) my->acc = a * ky;
```

**必须在 Begin 之后**，因为 Begin 第 212 行会把 `acc` 恢复成 `acc_cmd`。
这两行的位置是整个函数最容易写错的地方。

**【坑】**
1. 纯水平线（`dy=0`）时 `ny=0`、`ky=0`，Y 轴不启动，`v=feed` 全给 X → 等价于 `MOV`。
   功能正常，但 `CmdLine` 会接受 `LINE X10 F20`（Y 省略）。
2. `feed` 上限硬编码 200（第 435 行），而单轴 `vmax` 上限 60。
   斜线时如果 `kx=1`（纯 X），`v` 会被 `vmax/kx=50` 降下来，所以不冲突。
3. **加速时间相等但减速时间也相等**，靠的是两轴 `acc/|v|` 相同 → `t = v/a = vx/(a·kx) = feed/a`。
   所以"同时到达"是数学保证，不是调出来的。

**【考点】** 这就是项目二 DDA 插补的雏形：DDA 是"按整数累加决定每拍发哪个轴"，
本方法是"按比例分配连续速度，靠相位累加器各自取整"——精度同级，实现简单得多。

---

#### `Stepper_Stop(id)` —— 第 515 行｜**减速停**

**【作用】** 以设定加速度减到 0。点动松手、软限位前刹车、`STOP` 指令都用它。

**【逐行】**
```c
__disable_irq();
if (v_plan < 0.5f) { increment=0; v_plan=0; state=IDLE; }     // 还没动，直接停
else {
    d = v_plan*v_plan / (2*acc);        // 制动距离 mm：v²=2as 反解
    n = (int32_t)(d/delta) + 1;         // 换成脉冲，+1 是保险
    target = position + direction*n;    // 把目标改到"刹车终点"
    state  = DEC;
}
__enable_irq();
```

**【逐行要点】**
- `+1`：`d/δ` 截断会少 1 个脉冲，减速曲线可能算到"目标已在身后"，立即判定到位并急停。
  加 1 个脉冲的余量，让 `√(2as)` 曲线有地方收尾。
- **不改 `increment`**：让速度自然降下来，不是硬切。
- 这个函数被 `Planner_1ms` 的通信超时调用过，那时是**每毫秒调一次**；
  连续调用会不断把 `target` 往前推（`position` 也在前进），导致永远追不上 → 电机不停。
  这就是 F8 事故的根因，修法是加 `s_comm_trip` 一次性标志。

**【考点】** `Stop` 和 `Halt` 的区别？——`Stop` 改目标、走减速曲线（有余量、有方向性）；
`Halt` 直接封脉冲（瞬间失速、可能丢步但保证立刻停）。

---

#### `Stepper_Halt(id)` —— 第 552 行｜**立即停**

**【作用】** 硬限位、急停、回零触发、联动回滚用。不减速。

```c
__disable_irq();
increment = 0; v_plan = 0; state = IDLE; start_wait = 0; pulse_active = 0;
HAL_GPIO_WritePin(step, SET);      // 立刻把脉冲引脚抬回关断电平
__enable_irq();
```

**【逐行】**
- `pulse_active = 0` + 写高电平：如果中断正好发生在"脉冲拉低后、下一拍拉高前"，
  不写这一句引脚会一直保持低电平，光耦一直导通 → **驱动器以为脉宽无限长，可能过流或锁死**。
  这是硬件上必须处理的一步。
- `start_wait = 0`：取消方向等待，允许下一次 Begin 立刻重设。

**【坑】** `Halt` 之后 `target` 还是旧值，`position` 停在半路。下次 `Stop` 会基于
`position` 重新算目标，不会跳回去，这点是安全的。
但如果 `Halt` 前 `state==ACC` 且 `v_plan` 还有值，`Halt` 后 `GetSpeedMM` 返回 0（因为 state==IDLE），
界面显示速度 0 但电机可能因惯性还在滑行——这是机械问题，不是代码问题。

---

#### `Stepper_StopAll()` / `Stepper_HaltAll()` —— 第 570 / 576 行

只是两次调用。`StopAll` 用于通信超时，`HaltAll` 目前没被调用（保留给以后 `ESTOP` 的软版本）。

### 2.4 安全保护

#### `Stepper_OnLimitHit(id, side)` —— 第 585 行｜**硬限位**

**【作用】** EXTI 里调用，2 µs 内封脉冲。

**【逐行】**
```c
if (!s_limits_enabled) return;                     // 总开关关着 → 完全不动作
if (回零流程中 && side < 0) return;               // 回零本来就要撞负限位，不算故障
Stepper_Halt(id);
alarm = 1; alarm_code = ALM_LIMIT(1);
if (home_state != NONE) home_state = FAIL;
```

**【坑】**
1. 回零时**正限位**仍然报警（`side<0` 才豁免）。因为回零只往负向走，
   撞正限位说明方向接反或行程错乱，必须报错。
2. `s_limits_enabled` 默认 0。这是**调试期的必要妥协**：开关没接时输入浮空，
   上拉后可能一直是高电平 → 一上电就报警。但**验收 F5 必须置 1**，
   报告里也要写明这个开关的意义。

---

#### `Stepper_EmergencyStop(void)` —— 第 610 行

**【作用】** 硬件急停按钮和 `ESTOP` 指令共用的一条路径。

```c
for each axis:
    Halt(i);
    alarm = 1; alarm_code = ALM_ESTOP(2);
    homed = 0;                        // 急停后位置不可信 → 必须重新回零
    if (home_state != NONE) home_state = FAIL;
```

**【逐行考点】** 为什么 `homed = 0`？急停是瞬间失速，电机可能丢步几十个脉冲，
此时 `position` 与真实位置已经不符，绝对不能再用它做绝对定位。
**"急停后必须重新回零"是任务书 F7 的明确要求**。

---

#### `HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)` —— 第 624 行

**【作用】** HAL 的弱函数，被 `stm32f1xx_it.c` 的 `EXTIx_IRQHandler` 调用。

```c
switch (GPIO_Pin) {
case X_LIMIT_NEG_Pin: Stepper_OnLimitHit(STEPPER_X, -1); break;
... 4 个限位 ...
case EMERGENCY_STOP_Pin: Stepper_EmergencyStop(); break;
}
```

**【坑】** `switch` 是按**引脚号**匹配，不是按"端口+引脚"。
如果 X 负限位和 Y 负限位配在同一个引脚号（比如都是 PA0 和 PB0），
两个 `case` 值相同会编译报错；更隐蔽的是**同一端口不同引脚没问题，不同端口同引脚号才冲突**。
本项目分配在不同引脚号上（PA0~PA3 或类似），所以能编过。
**加轴或改引脚时必须检查这一点。**

#### `Stepper_EnableLimits(uint8_t enable)` —— 第 637 行

一行赋值。`main.c` 里由 `#define LIMITS_ENABLE` 控制是否调用。

### 2.5 回零（F4）

#### `Stepper_HomeTick(id)` —— 第 649 行｜**状态机核心**

**【作用】** 1 ms 调一次，推进 5 个阶段的回零流程。**这是全工程最值得逐行读的函数。**

**【总体结构】**
```c
home_timer++;                                   // 当前阶段计时
if (home_timer > 20000) { Halt; FAIL; alarm; }  // 超时保护
neg = 读负限位;
switch (home_state) { ... 7 个 case ... }
```

注意 `home_timer` 是**每阶段重置**的（每个 case 里切状态时都 `home_timer = 0`），
所以超时是"单阶段 20 s"，不是"整体 20 s"。5 个阶段最坏 100 s 才会全失败，
但实际上正常回零 5 s 内完成。

---

**case ① `HOME_FAST`（670 行）—— 快速趋近**
```c
if (neg) { Stepper_Stop(id); home_state = WAIT1; home_timer = 0; }
```
`HomeStart` 已经用 `home_fast`（10 mm/s）启动了负向连续运动。
这里只等开关触发，触发后**减速停**（10 mm/s 不快，允许减速，不会撞坏）。
**为什么不用 Halt**：10 mm/s 下急停会让滑块顿一下，长期伤丝杠。

---

**case ② `HOME_WAIT1`（679 行）—— 等停稳，慢速退出**
```c
if (!Stepper_IsBusy(id)) {
    if (Stepper_Start(id, +1, home_slow)) { home_state = BACKOFF; }
    else { FAIL; alarm; }
}
```
**为什么必须等 `!IsBusy`**：电机还在减速时反向，驱动器会收到方向突变，
可能丢步或过流。等 `state==IDLE` 才安全。
**注意**：这里调 `Stepper_Start(+1)` 时，`homing` 标志会让 `Begin` 跳过"禁止朝限位方向"的检查——
但我们是**离开**限位，方向是 +1，本来就不受限。真正需要豁免的是 ④ 阶段。

---

**case ③ `HOME_BACKOFF`（696 行）—— 等开关释放**
```c
if (!neg) { Stepper_Halt(id); home_state = WAIT2; home_timer = 0; }
```
用 `home_slow`（1 mm/s）正向走，开关一释放立刻 `Halt`。
这里用 Halt 不用 Stop：1 mm/s 下急停不会丢步（加速度需求极小），
而 Stop 会多走几毫米，把"释放点"的精度弄丢。

---

**case ④ `HOME_SLOW`（722 行）—— 二次趋近，触发即零点**
```c
if (neg) {
    Stepper_Halt(id);
    m->position = 0;              // ★ 机械零点定义在此
    home_state = WAIT3;
}
```
**这是回零精度的关键**：用 1 mm/s 二次趋近。
光电开关的触发点随速度变化——10 mm/s 时触发点和 1 mm/s 时能差 0.1~0.3 mm
（因为光斑边缘 + 响应延迟 + 减速距离）。1 mm/s 时这个离散度压到 0.01 mm 以内，
所以回零重复性能到 0.05 mm。

**为什么 Halt 而不是 Stop**：1 mm/s 的制动距离 = `v²/(2a) = 0.0025 mm`，
比一个脉冲当量（0.003125 mm）还小，急停不会丢步。而且需求是把"触发点"这个
物理位置精确定义为零点，多走一点都不行。

---

**case ⑤ `HOME_TOZERO`（749 行）—— 退到 +2 mm**
```c
Stepper_MoveRel(id, 2.0f, home_fast);   // WAIT3 里启动
if (!IsBusy) { homed = 1; home_state = DONE; }
```
退 2 mm 是为了让开关恢复"未遮挡"状态，否则一起动就又触发限位报警。
`homed = 1` 从此软限位、绝对定位才生效。

**【难点：`Stepper_Start` 和 `Stepper_MoveRel` 在回零里能成功吗】**
`Stepper_Begin` 第 185 行的检查是 `if (s_limits_enabled && !homing)`。
`homing` 的计算在第 179 行：只要 `home_state` 不在 {NONE, DONE, FAIL} 就为 1。
所以回零全程豁免硬限位方向检查——这是**必须的**，否则 ① 阶段一启动就被自己拦住。

---

#### `Stepper_HomeStart(id)` —— 第 762 行

```c
if (alarm || state != IDLE) return 0;
homed = 0;
home_state = HOME_FAST;
home_timer = 0;
return Stepper_Start(id, -1, home_fast);
```

**【顺序坑】** `home_state` 必须在 `Stepper_Start` **之前**设置，
否则 `Begin` 里的 `homing` 判断为假，负向启动会被限位检查拦下（如果限位已启用）。
同时 `homed=0` 必须清零，否则上一次的软限位会拦住回零。

```c

alarm = 0; alarm_code = 0;
homed = 0;                         // ★ 复位报警同时作废回零
```

**【考点】** 为什么复位报警要作废"已回零"？因为报警（限位/急停）发生时电机可能已经丢步，

### 2.7 参数设置（F9）

#### 10 个 Getter（第 869-878 行）

全部写成一行三元表达式：`return (id < STEPPER_NUM) ? motor[id].xxx : 0.0f;`
故意不用 `if`，因为 `GET` 每 100 ms 可能被调 10 次，能省几条指令就省。

#### `Stepper_VmaxLimit(m)` —— 第 881 行

```c
return 25000.0f * m->delta;
```

**这是速度的物理上限**。推导：
- K ≤ 2³¹ 保证每拍最多 1 个脉冲 → 输出频率 ≤ 50 kHz
- 但脉宽占 2 拍（一拍拉低、一拍拉高）→ **实际输出 ≤ 25 kHz**
- `v = f·δ` → `vmax = 25000·δ`

数值：1600 细分 → 78.125 mm/s；6400 细分 → 19.53 mm/s。
**换个细分，速度上限就变**，这就是为什么 `SetVmax` 要调它。

#### `Stepper_SetAccel(id, acc)` —— 第 886 行

范围 `[10, 500]`。下限 10 是因为太小了加速时间过长（50 mm/s 要 5 s）；
上限 500 是因为 57 步进电机在 5 mm 导程上再高就容易丢步。

#### `Stepper_SetVmax(id, vmax)` —— 第 896 行

```c
if (vmax < 1.0f || vmax > 60.0f) return 0;          // 机械上限（怕撞）
if (vmax > Stepper_VmaxLimit(&motor[id])) return 0;  // 电气上限（怕丢脉冲）
```

**两道限制缺一不可**：60 mm/s 是"机械上敢跑"，25 kHz×δ 是"电气上能发"。
6400 细分时电气上限只有 19.5，`SET VMAX=50` 会被拒——这时用户必须先降细分或接受低速。

#### `Stepper_SetSoftLimit(id, min, max)` —— 第 908 行

```c
if (min_mm >= max_mm) return;
```
只判大小关系，不判绝对值。范围检查在协议层 `CmdSet` 里做（`SLMIN ≥ 0`、`SLMAX ≤ 250`）。
**为什么这么分**：`SetSoftLimit` 是两层参数一起改的原子操作，
单独校验一个会误伤（改 SLMAX 时 SLMIN 还是旧值）。

#### `Stepper_SetLead(id, lead)` —— 第 917 行

`[1, 20]` mm。改完 `Recompute` → **`homed = 0`**。
导程变了，1 个脉冲对应的位移就变了，之前的坐标全部作废。

#### `Stepper_SetPPR(id, ppr)` —— 第 930 行

```c
for (i in 0..7) if (TABLE[i] == ppr) ok = 1;   // 必须命中 8 档之一
if (!ok) return 0;
ppr = ppr; Recompute(); homed = 0;
if (vmax > VmaxLimit()) vmax = VmaxLimit();    // ★ 主动降 vmax
```

**为什么必须查表**：细分必须与驱动器拨码一致（F9 要求 8 档）。
用户输 `PPR=1700` 是笔误，直接接受会让所有运动距离算错。
**为什么要主动降 vmax**：从 1600 切到 6400，δ 变成 1/4，电气上限从 78 降到 19.5。
如果不降，`vmax` 还留着 50，下次运动 `K` 会被钳在 2³¹ → 实际速度只有一半，
但 `v_plan` 显示 50 → **"速度设了 50 只有 19.5"的诡异现象**。

#### `Stepper_SetDirInv(id, inv)` —— 第 961 行

只在 IDLE 时允许。改完立即生效于下一次 `Begin`。

#### `Stepper_SetHomeFast` / `SetHomeSlow` —— 第 970 / 979 行

`[5,20]` 和 `[0.5,2]`。慢速下限 0.5 是因为再慢 K 太小、脉冲不均匀；
上限 2 是因为超过 2 mm/s 触发点离散就明显了。

### 2.9 运动记录（F12）

#### `Stepper_TraceArm(id)` —— 第 1007 行

#### `Stepper_TraceMarkStop(void)` —— 第 1025 行


#### `Stepper_TraceSample(id)` —— 第 1053 行｜**1 ms 采样**

```c
if (s_trace_axis != id) return;               // 不是被武装的轴，直接返回
if (!tr_on) {                                 // 还没开始记
    if (state != IDLE) { tr_on = 1; tr_n = 0; tr_last = position; }  // 运动开始了，从这拍起记
    return;
}
d = position - tr_last;  tr_last = position;  // 本毫秒的脉冲增量
if (d < 0) d = -d;                            // 取绝对值（方向单独看）
s_trace_buf[tr_n++] = d;
if (state == IDLE) tr_on = 0;                 // 到位，停止记录
```

**【逐行要点】**
- 记的是**增量**不是位置：`uint16_t` 一个点 2 字节，3000 点 6 KB。
  若记绝对位置，240 mm × 320 脉冲/mm = 76800 也放得下，但增量更通用（不限行程）。
- 位置由上位机做前缀和还原（`compute_trace`），这样精度不损失。
- 1 ms 内最多 78 个脉冲（25 kHz/2），远小于 uint16 上限 65535，不会溢出。
- `tr_on` 在"开始运动的那一拍"置位并 `tr_last = position`，所以第一个采样点是
  **下一毫秒**的增量，不会有"从上次运动残留的位置差"。

#### `Stepper_TraceAxis / TraceStopIndex / TraceCount / TraceGet` —— 第 1035-1050 行

四个读取接口，供 `CmdDump` 使用。`TraceGet` 检查 `i >= STEPPER_TRACE_MAX`
（不是 `>= tr_n`，因为 `CmdDump` 已经用 `n` 限定了范围，这里再防一次越界）。

### 2.10 两个中断体（最关键的两个函数）

#### `Stepper_Planner_1ms(void)` —— 第 1104 行｜**1 ms 规划**

**【作用】** SysTick 中断里调，每个轴每毫秒算一次当前应该跑多快。

**【逐行】**

```c
// ① 通信超时（1113-1119）
if (s_host_seen && !s_comm_trip && (HAL_GetTick() - s_last_rx_ms) > 500) {
    s_comm_trip = 1;  s_comm_lost = 1;
    Stepper_StopAll();
}
```
**这三个标志缺一不可**：
- `s_host_seen`：从没连过上位机时不该触发（脱机调试时不会莫名停车）
- `s_comm_trip`：**一次性**。这是 F8 事故的修复核心。
  `Stop` 会把 `target` 改成"当前位置 + 制动距离"，每毫秒调一次 → 目标永远在前方 → 电机不停。
- `s_comm_lost`：给界面显示"通信中断"用

```c
// ② 逐轴（1121-1126）
Stepper_TraceSample(i);          // 先采样（要在 increment 更新前，用上一毫秒的真实位置）
if (m->alarm) { m->increment = 0; continue; }    // 报警锁定，绝不发脉冲
```

```c
// ③ 回零优先（1136-1141）
if (home_state 在 {FAST..TOZERO}) Stepper_HomeTick(i);
```
回零状态机每毫秒推进一次，**在速度规划之前**，因为它可能改变 `state`/`target`/`position`。

```c
// ④ 空闲（1143-1148）
if (state == IDLE) { increment = 0; v_plan = 0; continue; }
```

```c
// ⑤ 方向建立期（1151-1152）
if (start_wait > 0) continue;     // 保持 increment 为 0，不发脉冲
```

```c
// ⑥ 制动速度上限（1154-1159）
remain = |target - position|;
v_brake = sqrtf(2.0f * acc * remain * delta);   // v ≤ √(2as)
```

```c
// ⑦ 状态机（1161-1190）
case ACC:
    v_plan += acc * 0.001f;                  // 按 a 上升
    if (v_plan >= v_cmd) { v_plan = v_cmd; state = CRUISE; }
    if (v_plan > v_brake) { v_plan = v_brake; state = DEC; }   // 短行程 → 三角形
    break;
case CRUISE:
    v_plan = v_cmd;
    if (v_plan > v_brake) { v_plan = v_brake; state = DEC; }
    break;
case DEC:
default:
    v_plan = v_brake;                        // 每毫秒重算 → 误差自校正
    break;
```

```c
// ⑧ 换算（1192）
m->increment = Stepper_SpeedToIncrement(m, v_plan);
```

**【为什么这三段能自动收尾】**
减速段每毫秒都用**当前剩余距离**重算速度，所以：
- 多走了 → `remain` 变小 → `v_brake` 变小 → 下一步慢下来
- 少走了 → `remain` 还大 → `v_brake` 还大 → 不会提前停

因此哪怕中间丢步（负载冲击），曲线也会自动纠正，最后一定停在 `target` 上。
**这就是"误差自校正"，也是这段代码比固定减速度表优越的地方。**

**【坑】**
1. `sqrtf` 每毫秒 2 次，Cortex-M3 无 FPU，软件浮点约 6 µs/次 → 12 µs，占 1 ms 的 1.2%，可以接受。
   如果加轴到 4 轴，就考虑查表或定点。
2. `v_brake` 在 `remain==0` 时为 0，此时若 `state==ACC` 且 `v_cmd>0`，
   会立刻 `v_plan=0, state=DEC`，然后 `increment=0`，**但 state 不会自动变 IDLE**，
   只能等节拍层 `position==target` 的判定。如果 `position` 恰好已经等于 `target`，
   节拍层那一句 `if (state != IDLE && position == target)` 会立即把状态清成 IDLE——
   这就是 `MoveRel` 里 `n==0` 必须拦掉的另一个原因。
3. `HAL_GetTick()` 在 SysTick 中断里读 `uwTick`，**SysTick 中断本身就在这个函数里**，
   所以 `uwTick` 还没自增（HAL_IncTick 的调用顺序取决于 stm32f1xx_it.c）。
   差异最多 1 ms，对 500 ms 超时无影响。

#### `Stepper_Axis_Tick(StepperAxis *m)` —— 第 1199 行｜**50 kHz 节拍**

**【作用】** 全工程唯一产生 STEP 脉冲的地方。

**【逐行】**
```c
// ① 释放上一拍拉低的脉冲（1203-1208）
if (pulse_active) { STEP写高; pulse_active = 0; }
```
**这就是"脉宽 = 2 拍 = 40 µs"的来源**：本拍拉低，下一拍拉高。
驱动器要求脉宽 ≥ 2.5 µs，40 µs 非常宽裕，光耦（6N137 之类，1 Mbps 级）跟得上。

```c
// ② 方向建立等待（1211-1215）
if (start_wait > 0) { start_wait--; return; }
```
50 拍 = 1 ms。**注意这段在"释放脉冲"之后**，所以等待期间不会有残留低电平。

```c
// ③ 速度为 0（1217-1218）
if (increment == 0) return;
```

```c
// ④ 相位累加（1220-1223）
old_phase = phase;
phase += increment;
```

```c
// ⑤ 溢出检测（1226）
if (phase < old_phase) { ... }
```
**为什么用"变小了"判断溢出**：32 位无符号加法溢出会回绕，`new < old` 就是溢出。
比判断"是否 ≥ 2³²"快，而且不需要 64 位运算。

```c
// ⑥ 出脉冲（1228-1231）
STEP写低; pulse_active = 1;
position += direction;
```

```c
// ⑦ 到位判断（1234-1239）
if (state != IDLE && position == target) {
    increment = 0; v_plan = 0; state = IDLE;
}
```
**为什么可以用 `==` 而不用 `>=`**：规划层保证不会超调——
`v_brake` 每个毫秒都限制住"剩下的距离够不够刹"，再加上 `Stop` 里 `+1` 的余量，
实际总是"恰好到达"。用 `==` 是"如果超调了就说明有 bug，不要掩盖它"的态度。
（如果将来加了位置突变，这里必须改成"越过就停"。）

**【坑】**
1. 这段代码在 50 kHz 中断里执行，两个轴共 ~40 条指令，20 µs 预算下占约 15%（72 MHz 下 40 条指令 ≈ 0.6 µs，实际 3%）。
   **绝对不能在里加 `printf`**。
2. `HAL_GPIO_WritePin` 是函数调用，有 HAL 的检查开销。追求极致可以换成
   `GPIOx->BSRR = pin` 直接写寄存器，能再快 5 倍。当前速度够用，不必改。

## 3. `protocol.c` 逐函数

### 3.1 发送与格式化

#### `Send(const char *s)` —— 第 41 行

```c
HAL_UART_Transmit(&huart1, (uint8_t*)s, strlen(s), 200);
```
**阻塞发送，超时 200 ms**。在 115200 下，`<ST>` 帧约 60 字节 = 5.2 ms。
这就是为什么状态上报只能在主循环发，不能在中断发。

#### `ReplyOK()` / `ReplyErr(code)` —— 第 46 / 51 行

`"OK\r\n"` 和 `"ERR,%u\r\n"`。协议层所有指令都必须有且只有一个应答（`DUMP` 和 `TRACE` 除外，
`DUMP` 的应答是一整块多行数据）。

#### `FmtF(char *p, float v, uint8_t dec)` —— 第 60 行｜**浮点转文本**

**【作用】** 手写浮点格式化，**不用 `%f`**。

**【为什么】** Keil MicroLIB 默认不支持浮点格式化；即使支持，`%f` 会拉进
几 KB 的浮点库，20 KB RAM 的 F103C8 吃不消。所以自己写。

**【逐行】**
1. 负数先输出 `'-'`，取绝对值。
2. `scale = 10^dec`。
3. `ip = (uint32_t)v` 取整数部分；`fp = (v - ip)*scale + 0.5` 取小数部分并四舍五入。
4. **进位处理**：`if (fp >= scale) { ip++; fp -= scale; }`。
   没有这两行，`9.999` 保留 2 位会输出 `9.100`（因为 fp 变成 100）。
   **这是手写格式化最容易漏的地方。**
5. 先写整数（`sprintf %lu`），写小数点。
6. 小数部分用取模倒序放进 `tmp[]`，再倒着输出。
7. **补零**：`while (n < dec) tmp[n++] = '0';` 让 `1.5` 输出成 `1.500` 而不是 `1.5`。
   上位机按固定位置解析字段的假设就靠这个。

**【坑】** `tmp[8]` 只够 `dec ≤ 8`。当前最大 `dec=6`（DELTA），安全。

### 3.2 解析工具

#### `SkipSpace` —— 第 105 行｜跳空格和 Tab
#### `ToUpper` —— 第 113 行｜整串大写化，让 `jog x+ f20` 也能用
#### `ParseAxis(char **pp)` —— 第 124 行

**用二级指针**：既返回轴号又推进游标，所以调用处是 `axis = ParseAxis(&p)`，
之后 `p` 已经指向轴号后面的字符。这是 C 里解析命令行最省事的手法。

#### `ParseFloatAfter(char *p, char key, float *out)` —— 第 135 行

**【作用】** 在串里找 `F20` / `f20` 这种"关键字+数字"，找到就取出来。

```c

    if (*p == key || *p == key+32) {          // 大小写都认
        q = p+1;  v = strtof(q, &end);

```

**【逐行考点】** `end != q` 这个判断必须写：`"F"` 后面没数字时

### 3.3 状态上报

#### `StateName(id)` —— 第 158 行

```c
if (IsAlarm(id)) return "ALM";
if (IsHomed(id)==0 && IsBusy(id)) return "RUN";   // 这句和下一句等价，冗余
if (IsBusy(id)) return "RUN";
return "IDLE";
```
**第一句 `if` 是历史遗留**（早期想区分"未回零的运动"），现在冗余但无害。
答辩如果被问"这里为什么写两遍"，诚实回答"早期写法，可以合并"。

#### `SendStatus(void)` —— 第 169 行

**【作用】** 拼装并发送 `<ST ...>` 帧。**全工程最需要小心的函数：不能缓冲区溢出。**

帧格式（每个轴 4 个字段）：
```
<ST X=1.234,20.00,RUN,H1 Y=0.000,0.00,IDLE,H0 LIM=0100 ALM=0>
```

**【逐行】**
- `buf[144]`：最坏情况 X 位置 8 字符 + 速度 6 + 状态 4 + `H1` + 逗号 ≈ 25 字符/轴，
  两轴 50 + `LIM=` 8 + `ALM=` 6 + 尖括号 ≈ 70。144 有 2 倍余量。
- 用 `*p++ = 'X'` 逐字符写而不用 `sprintf`：避免格式串开销，也避免 `%f`。
- 第 209-212 行：`ALM` 取两轴报警码的**较大值**（协议只上报一个整机报警字段）。
  这就是上位机里 `self.status.alarm` 是整机字段、没有 `status.x.alarm` 的原因。
- 最后 `*p = '\0'` 然后一次 `Send`。**不逐段发送**，避免帧被打断。

**【考点】** 为什么 100 ms 上报一次？——任务书 F10 要求 ≥ 5 Hz。100 ms = 10 Hz，
既满足要求，又不会把串口占满（每帧 60 字节/100 ms = 600 B/s，115200 的 5%）。

所以 `RESET` 和 `RESET X` 效果一样——都清两轴。上位机的"复位"按钮也是发 `RESET`。

#### `CmdTrace` —— 第 520 行

轴号 → 忙 → `TraceArm`。**必须 IDLE 才能武装**，否则"运动已开始"的记录会缺前半段。

#### `CmdDump` —— 第 547 行｜**唯一的多行应答**

```c
sprintf(buf, "<TR %c N=%u DT=1 STOP=%u>\r\n", 'X'/'Y', n, stop);
Send(buf);
for (i=0; i<n; i++) { sprintf(buf,"%u\r\n", TraceGet(i)); Send(buf); }
Send("<TREND>\r\n");
```

**【逐行】**
- 头帧告诉上位机"共 n 点、采样周期 1 ms、停止标记在 stop 号"。
- 数据行就是纯数字，一行一个点。3000 点 × 6 字节 ≈ 18 KB，
  115200 下 1.6 s 传完。
- `<TREND>` 是结束哨兵。**没有它，上位机无法区分"传完了"和"断线了"**。
- `stop == 0xFFFF` 时输出 `STOP=-1`，上位机按 -1 处理（不画竖线）。

**【坑】** `buf[64]`，`sprintf("%u")` 最多 5 位，安全。
但 `Send` 是阻塞的，3000 次调用会占主循环约 1.6 s。这期间串口接收中断照常工作，
新指令会堆在环形缓冲里（256 字节），**所以 DUMP 期间不要发别的指令**。
上位机 `on_dump_trace` 里 `expect_ack=False` 也是这个原因。

#### `CmdGet` —— 第 576 行

拼一行 `OK X LEAD=5.000 PPR=1600 DIRINV=0 ACC=200.0 VMAX=50.00 SLMIN=0.000 SLMAX=240.000 HF=10.00 HS=1.00 DELTA=0.003125`。

**【逐行】** 用 `q += sprintf(q, "...")` 累积写指针，浮点用 `FmtF`。
`out[120]`：最坏情况约 110 字符，勉强够。**如果再加两个参数就要扩容**。

**【考点】** 为什么 GET 的应答不是 `OK` 而是 `OK X ...`？
因为上位机要区分"普通 OK"和"带数据的 OK"。`parse_reply` 返回 `("ok_data", payload)`。

#### `CmdSet` —— 第 615 行｜**最长的解析函数**

```
SET X LEAD=5 PPR=1600 DIRINV=0 ACC=200 VMAX=50 SLMIN=0 SLMAX=240 HF=10 HS=1
```

**【逐行】**
1. 轴号 → 报警 → 忙（这三个是"改参数的前提条件"）。
2. `while(1)` 循环：
   - 跳空格，若到串尾 `break`。
   - 取键名到 `'='` 为止，放进 `key[12]`。
   - 若当前字符不是 `'='` → `bad=1; break`。
   - `strtof` 取值，`p` 被更新到数字后面。
   - 一串 `strcmp` 分派到 9 个 Set 函数。
   - `SLMIN`/`SLMAX` 特殊处理：因为 `Stepper_SetSoftLimit` 是改一对值，
     这里要取出另一半当前的值得以组成合法区间。
3. `bad` → `ERR,5`；`!changed`（一个参数都没匹配上）→ `ERR,1`。

**【坑】**
1. `key[12]`：`DIRINV` 6 字符够用。如果加 `HOMEOFFSET` 这种 10 字符键就会截断。
2. `bad=1` 后**已经生效的参数不会回滚**。比如 `SET X ACC=200 PPR=1234`，
   ACC 已经改了，PPR 失败，回 `ERR,5`。上位机看到 ERR 会以为全失败。
   **正确做法是先全部校验再全部应用**，但那样要写两遍分派。当前取舍：
   上位机一次只下发一个参数（`on_write_params` 每次只传一个键），所以实际不会遇到。
3. `strtof(q, &p)` 里 `p` 是 `char*` 的引用，直接接收新游标，和 `ParseFloatAfter` 的风格不同。

#### `CmdHelp` —— 第 749 行

一行列出所有指令名。**加新指令时记得同步改这里**，否则 HELP 会漏。

### 3.5 分派与主循环

#### 分派表 `s_cmds[]` —— 第 764 行

```c
typedef struct { const char *name; void (*fn)(char *args); } CmdEntry;
static const CmdEntry s_cmds[] = { {"PING", CmdPing}, ... };
```

**【为什么用函数指针表而不是 if-else 链】**
1. 加指令只加一行，不动控制流（开闭原则）。
2. 查表是 O(n) 字符串比较，但 n=14，最坏 14 次 `strcmp`，几微秒，无所谓。
3. **项目三要加 `G00/G01` 时，只需在这里加两行**——这就是代码注释里那句话的意思。

#### `Dispatch(char *line)` —— 第 784 行

```c
p = SkipSpace(line);
if (*p == '\0') return;                  // 空行忽略，不回 ERR（重要）
{
    char word[12]; uint8_t n = 0; char *q = p;
    while (*q && *q!=' ' && *q!='\t' && n < 11) word[n++] = *q++;
    word[n] = '\0';
    ToUpper(word);                        // 指令名大小写不敏感
    for (i...) if (strcmp(word, s_cmds[i].name)==0) { s_cmds[i].fn(q); return; }
}
ReplyErr(PROTO_ERR_UNKNOWN);              // 7
```

**【逐行考点】**
- **空行不回错误**：上位机发 `\r\n` 或者线路噪声产生空行时，不应该刷一屏 `ERR,7`。
- `word[12]`：最长指令名 `ESTOP` 5 字符，够。
- `q` 指向指令名之后的第一个字符（可能是空格），传给 `fn` 前各 `Cmd` 自己 `SkipSpace`。
- **未知指令回 `ERR,7`**，不回 `OK`——这样上位机能发现拼写错误。

#### `Protocol_Init(void)` —— 第 821 行

```c
s_rx_head = s_rx_tail = 0;  s_line_len = 0;  s_status_last = HAL_GetTick();
HAL_NVIC_SetPriority(USART1_IRQn, 3, 0);      // ★ 串口优先级最低
HAL_UART_Receive_IT(&huart1, &s_rx_byte, 1);  // 武装单字节接收
```

**【逐行考点】** 第 829 行是**整个安全设计的关键**：
USART1 优先级 3（最低），限位 EXTI 优先级更高（在 `gpio.c` 里配的），
所以限位中断可以打断串口中断——**保证"撞上开关"比"收完一条指令"更优先**。

**为什么用单字节 `Receive_IT` 而不是 DMA**：
1. 代码简单，不依赖 DMA 通道分配。
2. 115200 下每字节 87 µs，进一次中断几微秒，CPU 占用 5% 左右，可接受。
3. DMA + 空闲中断是更好的方案（项目二/三可以考虑），但会引入"半包"处理复杂度。

#### `HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)` —— 第 835 行

```c
next = (s_rx_head+1) % PROTO_RX_SIZE;
if (next != s_rx_tail) { s_rx_buf[s_rx_head] = s_rx_byte; s_rx_head = next; }
HAL_UART_Receive_IT(&huart1, &s_rx_byte, 1);    // 重新武装（必须！）
```

**【逐行考点】**
1. **环形缓冲留一个空位**：`next != tail` 而不是 `next != head`。
   这样"满"和"空"能区分开（满：`next==tail`；空：`head==tail`）。
2. **满了丢新字节，不覆盖旧字节**：宁可丢新数据也不破坏正在解析的旧行。
3. **必须重新调用 `Receive_IT`**：HAL 的单字节接收是"一次性"的，
   不重新武装就只收到第一个字节，之后串口"死掉"。这是 HAL 最经典的坑。

#### `HAL_UART_ErrorCallback` —— 第 853 行

```c
__HAL_UART_CLEAR_OREFLAG(huart);          // 清溢出标志
HAL_UART_Receive_IT(&huart1, ...);         // 重新武装
```

**【为什么必须有】** ORE（溢出）错误发生后，HAL 会中止接收且不再触发回调。
不处理的话，一次噪声或一次 `Send` 阻塞期间的溢出就会让串口永久失效，
表现是"上位机发什么都不响应，只能重新上电"。

#### `Protocol_Poll(void)` —— 第 862 行｜**主循环唯一入口**

```c
// ① 组行
while (head != tail) {
    c = buf[tail]; tail = (tail+1) % SIZE;
    if (c == '\n') {
        s_line[s_line_len] = '\0';
        if (s_line_len > 0) { Stepper_NoteHostMessage(); Dispatch(s_line); }
        s_line_len = 0;
    } else if (c != '\r') {
        if (s_line_len < 95) s_line[s_line_len++] = c;
        else s_line_len = 0;                      // 超长行丢弃
    }
}
// ② 100 ms 上报
if (HAL_GetTick() - s_status_last >= 100) { s_status_last = HAL_GetTick(); SendStatus(); }
```

**【逐行考点】**
1. **`\r` 被忽略，`\n` 作为行结束**：这样 `\r\n` 和 `\n` 都能正确分帧。
2. **只在"非空行"时调 `NoteHostMessage`**：空行不刷新心跳（严格但也合理）。
3. **超长行丢弃**：`s_line_len = 0` 后继续接收，直到下一个 `\n`。
   这样一条 200 字节的垃圾数据不会破坏后续正常指令。
4. **100 ms 上报用 `HAL_GetTick` 差值**，不用计数器：
   `HAL_GetTick()` 溢出（49 天）时差值仍然正确（无符号减法）。**这是标准做法**。
5. **`SendStatus` 在主循环**：阻塞 5 ms 不影响脉冲（脉冲在中断里），
   但会延迟指令响应。所以指令应答永远优先于状态上报（先处理完缓冲再上报）。

## 4. `main.c` 与中断时序

### 4.1 `main()` 的初始化顺序（第 117-160 行）

```c
HAL_Init();                  // SysTick 1 ms 启动，Flash 预取等
SystemClock_Config();        // HSE 8M × 9 = 72 MHz
MX_GPIO_Init();              // 引脚 + EXTI（限位、急停）
MX_TIM2_Init();              // TIM2：72M/72/20 = 50 kHz，只配不启动
MX_USART1_UART_Init();       // 115200 8N1
Stepper_Init();              // 轴对象 + 引脚绑定 + δ/K 计算
HAL_TIM_Base_Start_IT(&htim2);// ★ 启动 50 kHz 中断
#if LIMITS_ENABLE
Stepper_EnableLimits(1);
#endif
Protocol_Init();             // 串口中断武装
#if HOME_ON_BOOT
Stepper_HomeStart(STEPPER_X);
#endif
while (1) { Protocol_Poll(); }
```

**【顺序的三个理由】**
1. `Stepper_Init` 依赖 GPIO 已初始化（要写引脚）。
2. `TIM2` 启动要在 `Stepper_Init` 之后，否则中断里用到未初始化的 `delta`（=0）。
3. `Protocol_Init` 最后，这样串口一开就能正常响应（轴已经准备好了）。

**【`LIMITS_ENABLE` 和 `HOME_ON_BOOT` 两个宏】**
- `LIMITS_ENABLE=0`：限位保护关。**验收 F5 前必须改成 1**，
  前提是用万用表确认"未遮挡=低、遮挡=高"。
- `HOME_ON_BOOT=0`：上电不自动回零，等上位机发 `HOME`。
  改成 1 时注意只回 X 轴（Y 轴需要手动加，因为两轴同时回零可能撞干涉）。

### 4.2 `HAL_TIM_PeriodElapsedCallback`（第 232 行）

```c
if (htim->Instance == TIM2) Stepper_TIM_Callback();
```
HAL 的定时器中断统一入口，必须判 `Instance`，否则其他定时器（如果以后加）会误触发。

### 4.3 SysTick 里调规划（`stm32f1xx_it.c`）

```c
void SysTick_Handler(void) {
    HAL_IncTick();
    Stepper_Planner_1ms();       // ★ 必须加在 HAL_IncTick 之后
}
```

**【为什么必须在 `HAL_IncTick()` 之后】** 规划里用 `HAL_GetTick()` 判通信超时。
如果放在之前，`uwTick` 还是上一毫秒的值，超时判断会多 1 ms 延迟——影响不大，
但逻辑上不对。更重要的是：`HAL_Delay` 依赖 `uwTick`，如果规划函数耗时过长会拖慢所有 HAL 延时。

### 4.4 中断优先级全表（要能背下来）

| 中断 | 优先级 | 抢占 | 理由 |
|---|---|---|---|
| EXTI（限位/急停） | 0~1 | 最高 | 撞了必须 2 µs 内封脉冲 |
| TIM2（50 kHz） | 2 | 高 | 脉冲节拍不能等，等一拍就少一个脉冲 |
| SysTick（1 ms） | 15（HAL 默认） | 最低 | 规划晚 1 ms 不影响位置精度（自校正） |
| USART1 | 3 | 次低 | 收字节可以等，反正有环形缓冲 |

**【关键结论】** 极限情况下（限位触发 + 正在发脉冲 + 正在收串口），
限位中断会打断一切，立即 `Halt`。**这就是三层安全里"硬限位"能救命的原因。**

### 4.5 `usart.c` / `gpio.c` / `tim.c` 里要确认的三处

1. `tim.c`：`Prescaler=71, Period=19` → 72 MHz/(71+1)/(19+1) = 50 kHz。
2. `gpio.c`：4 个限位 + 1 个急停都配成 `GPIO_MODE_IT_RISING`（上升沿），
   `Pull=PULLDOWN`**或** `PULLUP`——这取决于你的开关类型，当前代码假设"高=触发"。
3. `usart.c`：`BaudRate=115200, WordLength=8B, StopBits=1, Parity=NONE`。

### 5.3 `serial_link.py`（105 行）—— 通信线程

#### `class SerialWorker(QThread)` —— 第 29 行

**四个信号**：`line_received(str, float)` / `opened` / `closed` / `failed(str)`。

**【为什么必须放线程】** 任务书 4.3.5 明确要求。技术上：
`serial.read()` 在没数据时会阻塞（虽然设了 `timeout=0.02`），
如果放主线程，界面会每 20 ms 卡一次，鼠标拖动都不顺。

**【`run()` 逐行】**
```python
self._ser = serial.Serial(..., timeout=0.02, write_timeout=0.5)   # 打开
self.opened.emit()                                                 # 通知界面
while not self._stop:
    # ① 发送队列（一次清空）
    while True:
        try: text = self._tx.get_nowait()
        except queue.Empty: break
        if not text.endswith("\n"): text += "\r\n"                 # 自动补换行
        self._ser.write(text.encode("ascii", errors="ignore"))
    # ② 接收（有多少读多少，没有就读 1 字节等 20 ms）
    n = self._ser.in_waiting
    data = self._ser.read(n if n > 0 else 1)
    if not data: continue
    # ③ 按 \n 切行
    self._buf.extend(data)
    while b"\n" in self._buf:
        raw, _, rest = bytes(self._buf).partition(b"\n")
        self._buf = bytearray(rest)
        line = raw.decode("ascii", errors="ignore").strip("\r\n ")
        if line: self.line_received.emit(line, time.time()*1000)
    # ④ 防爆缓冲
    if len(self._buf) > 4096: self._buf.clear()
```

**【六个知识点】**
1. **队列而不是锁**：`send()` 只 `put`，不碰串口对象 → 界面线程零阻塞。
   `queue.Queue` 本身线程安全。
2. **`timeout=0.02`**：读不到数据 20 ms 后返回，循环继续检查 `_stop`。
   这样 `stop()` 后最多 20 ms 线程退出。**这就是"线程能优雅关闭"的关键。**
3. **`in_waiting` 优先**：有数据一次全读，效率高；没数据才阻塞等。
4. **组帧靠自己**：pyserial 的 `readline()` 在超时后会返回半行，
   自己用 `bytearray` + `partition(b"\n")` 组帧才能保证"一行就是一行"。
5. **`errors="ignore"`**：中文注释的指令或噪声字节不会抛 `UnicodeDecodeError`。
6. **4096 上限**：如果下位机一直发但换行符丢失（协议错乱），
   缓冲会无限增长吃内存。超过 4 KB 直接清空，宁可丢数据也不让程序崩。

### 5.4 `trace_plot.py`（119 行）—— 自绘曲线

**【`_apply_state` 的四条规则（答辩必考）】**
```python
connected = conn_state in (OK, LOST)     # 曾经连上过 → 允许断开/急停

params:        link_ok and not alarm and not busy
btn_arm:       link_ok and not alarm
btn_dump/csv:  connected
AxisPanel:     refresh_enabled(connected, alarm, busy)
```

**为什么 `btn_estop` 只要 `connected` 而不是 `link_ok`**：
通信中断时，用户最需要的就是"急停"。即使链路可能已经断了，
也应该允许尝试发送——万一只是状态帧丢了而指令通道还好呢。
**这是安全设计上的"宁可多发"原则。**

**【`on_line` 的五路分支顺序为什么不能改】**
```python
st = parse_status(line)        # ① <ST ...>
if st: ...
hdr = parse_trace_header(line) # ② <TR X N=...>
if hdr: ...
if line == "<TREND>":          # ③
if self._dumping: ...          # ④ 纯数字行
kind, payload = parse_reply(line)  # ⑤ OK/ERR/PONG
```
如果把 ⑤ 放在前面，`DUMP` 的数据行（纯数字）会被 `parse_reply` 判成 `None`，没问题；
但 `_dumping` 期间如果来了一个 `<ST>` 帧（100 ms 上报不会停），
会先被 ① 捕获拿去刷新界面，**不会污染 `_dump_lines`**——这是对的。
**关键点：`_dumping` 判断必须在 `parse_reply` 之前，因为数据行可能恰好是 "OK" 之类的字符串？**
不会（数据行是数字），但顺序上"先排除已知格式，再处理应答"更安全。

**【`on_line` 的命名坑（真实事故）】**
最初联动槽函数也叫 `on_line`，与串口接收同名。Python 中后定义的方法会**覆盖**先定义的，
结果每次收到状态帧都去调联动逻辑，参数不匹配抛 `TypeError`，
异常在 Qt 信号回调里被吞掉 → **所有按钮永久变灰、界面像死了一样**。
改名 `on_line_move` 后恢复。**教训：Qt 槽函数命名要带业务后缀，不要用通用名。**

**【`send_estop` 为什么不走 `send()`】** `send()` 会写 `_pending` 并期待 `OK` 应答。
急停时下位机可能已经忙得回不了 OK，堆积无意义的 pending 会让"应答超时"刷屏。
所以直接 `worker.send()` + 手动写记录。

### 链路 A：`JOG X+ F20`（点动）

| 时刻 | 位置 | 发生什么 |
|---|---|---|
| t0 | 上位机 | `on_jog("X", +1, 20)` → `send("JOG X+ F20")` → 入队 |
| +1 ms | 线程 | `run()` 取出，补 `\r\n`，写串口 |

| +3 ms | `CmdJog` | 解析 → `Stepper_Start(0, +1, 20)` |
| +3 ms | `Stepper_Start` | `target = position + 96000`，软限位钳位 |
| +3 ms | `Stepper_Begin` | 关中断 → DIR=高 → `start_wait=50` → `state=ACC` → 开中断 |
| +4~53 ms | TIM2 ×50 | `start_wait--`，无脉冲 |
| +54 ms | 规划 | 第一次 `v_plan = 200×0.001 = 0.2`，`K = 0.2×2.75e7 = 5.5e6` |

| 松手 | 上位机 | `send("STOP X")` |
| +几 ms | `Stepper_Stop` | `d = 20²/400 = 1 mm`，`n = 320+1`，`target = pos+321`，`state=DEC` |
| 之后 100 ms | 规划 | `v_plan = √(2×200×remain×0.003125)` 逐毫秒下降 |
| 到位 | TIM2 | `position == target` → `increment=0, state=IDLE` |

### 链路 B：`LINE X10 Y-5 F20`（斜线联动）

| 步骤 | 计算 |
|---|---|
| 位移 | `nx = 10/0.003125 = 3200`，`ny = -5/0.003125 = -1600` |
| 反算 | `lx = 3200×δ = 10.000`，`ly = 1600×δ = 5.000` |
| 长度 | `len = √(100+25) = 11.180` |
| 比例 | `kx = 0.8944`，`ky = 0.4472`（比值 2:1，与位移比严格一致） |
| 速度 | `vx = 20×0.8944 = 17.888`，`vy = 20×0.4472 = 8.944`（都 < 50，不降速） |
| 加速度 | `a = min(200/0.8944, 200/0.4472) = min(223.6, 447.2) = 223.6` |
| 实际 | `ax = 223.6×0.8944 = 200`，`ay = 223.6×0.4472 = 100` |
| 加速时间 | `t = 20/223.6 = 89.4 ms`（两轴相同） |
| 到位 | 两轴同拍触发 `position==target` |
| 验证 | 任意时刻 `vx/vy = 2.000`，`ΔX/ΔY = 2.000`，全程偏差 0.000 mm |

**参考答案要点**（只给关键，自己展开）：
1. K>2³¹ 时一拍可能溢出两次，代码只检测一次 → 丢脉冲 → 位置与频率不符。
2. 大小与方向分离；方向在 `direction`（±1）；对外用 `GetSpeedMM` 合成。
3. 联动时要临时缩放生效值，但不能污染用户设定值；`Stepper_MoveLine`。
4. 补截断误差，给减速曲线留收尾余量；去掉后可能"目标已在身后"→ 立即急停、有异响。
5. `Stop` 改目标为"当前位置+制动距离"，重复调用会让目标永远在前方 → 电机不停（F8 事故）。
6. 10 mm/s 时触发点离散 0.1~0.3 mm，1 mm/s 时 <0.01 mm；因为光斑边缘+响应延迟+制动距离都随速度变化。
7. 1 mm/s 的制动距离 0.0025 mm < 一个脉冲当量 0.003125 mm，急停不丢步，且能精确定义零点。
8. 回零本来就要撞负限位（预期信号）；撞正限位说明方向反了或行程错乱（故障）。
9. 前面第 185 行的检查可能被中断打断，关中断后判的才是权威值（TOCTOU 防护）。
10. 两轴都等 50 拍，主循环调用的微秒级时间差被 1 ms 吸收 → 第 51 拍同时起步。
11. 用户给的 dx/dy 与最终发出的脉冲数差一个取整，比例会失真 → 末端多走出斜线。
12. 只限一轴会改变速度比例 → 轨迹拐弯；整体降速保持比例（等同进给倍率）。
13. `Stepper_Begin` 第 212 行会把 `acc` 恢复成 `acc_cmd`，覆盖必须在它之后。
14. 40 µs（2 拍 × 20 µs）；50% 占空比；上限 25 kHz 由此而来。
15. 32 位无符号加法溢出会回绕，`new < old` 即溢出，比判 ≥2³² 快且不用 64 位。
16. 规划层保证不超调；若将来允许位置突变（如回零改 position）必须改成越过就停。
17. 否则 `state=ACC` 但 `remain=0`，`IsBusy` 永远为 1 → 界面卡在"运行中"。
18. `9.999` 保留 2 位会输出 `9.100`（fp 变成 100 没进位）。
19. HAL 单字节接收是一次性的，不重新武装就只收第一个字节，之后串口"死掉"。
20. ORE 后 HAL 中止接收且不再回调 → 串口永久无响应，只能重新上电。
21. 留一位才能区分"满"和"空"；`next != tail` 是"未满"，`next != head` 永远成立（写法错误）。
22. 协议帧只有一个 ALM 字段，两轴取最大（报警码越大越严重：1限位 < 2急停 < 3回零失败？实际按数值取最大）。
23. `HAL_UART_Transmit` 阻塞 5 ms，中断里做会拖住脉冲节拍 → 丢脉冲。
24. 安全设计"宁可多发"：通信中断时用户最需要急停，不能因为状态帧丢了就不让按。
25. 避免第一帧到达前界面代码读 `self.status.x` 抛 `AttributeError`。
26. 不能随意调换；`_dumping` 判断必须在 `parse_reply` 之前，否则数据行可能被误判。
27. 读不到数据 20 ms 后返回，循环才能检查 `_stop`；否则 `read()` 永久阻塞，关窗口就崩。
28. `_apply_state` 管"连接/报警/整体"级；`_refresh_status_widgets` 每帧都跑，管"单轴/联动"级；
   分开是为了避免每 100 ms 重建连接状态文字（会闪）。

## 9. 还差的一步

代码层面你已经能看到每个字节的去向了。剩下的两个未知数只有硬件：

1. `LIM=1111` 到底代表什么 —— 取决于你的光电开关是 NPN 常开还是常闭，
   以及 `gpio.c` 里配的是上拉还是下拉。**用万用表量一次就定了**，
   量完把 `LIMITS_ENABLE` 改成 1，验收 F5 就有实测数据。
2. 回零时电机会不会真的撞到机械挡块 —— 先手动把滑块放到中间，
   发 `HOME X`，观察它是否在开关处减速停住。第一次试的时候手放在电源开关上。

把这两件事做完，任务书里 F1~F12 就全部有实测支撑了。
